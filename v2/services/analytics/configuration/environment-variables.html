DIAL Analytics environment variables

This reference covers environment variables for platform engineers operating DIAL Analytics. It assumes the service connections are configured.

Defaults​

Defaults come from the application.yml and configuration documentation. — means no configured value. Actual defaults containing localhost are reproduced unchanged; container deployments need reachable service names.

Container environment​

Source: configuration reference.

VariableDefaultDescription
USE_SYSTEM_CA_CERTS—Any non-empty value (1, true, yes) imports certificates mounted into /certificates/ at startup.
JAVA_OPTS—Extra JVM arguments appended to the launch command.
DEBUG_OPTS—JVM debug arguments, applied before JAVA_OPTS.
SPRING_CONFIG_ADDITIONAL_LOCATION—External YAML/properties location overriding any property here.

Server​

Source: configuration reference.

VariableDefaultDescription
HTTP_PORT5000Port ADAS serves the API on.
MANAGEMENT_SERVER_PORT—Separate port for the /actuator endpoints (probes, info, Prometheus); unset serves them on HTTP_PORT.

Scheduled task execution​

Source: configuration reference.

VariableDefaultDescription
SCHEDULING_POOL_SIZE4Threads shared by the blob poller, the daily sync, the ingest retry sweep, and the level-file poll; below three a slow job delays another. Takes effect at startup.

Data sync schedule​

VariableDefaultDescription

SYNC_DAY_OFFSET1Days back from today to target; 1 is yesterday.
SYNC_BATCH_SIZE10000Rows per INSERT batch. At least 1.
SYNC_MAX_BATCH_BYTES134217728Byte ceiling per INSERT batch, flushing on whichever bound is hit first. Budget this per target per in-flight run. Between 1 MiB and 357913941.
SYNC_MAX_LINE_BYTES67108864Max decompressed bytes of one log line; a longer line is skipped and counted as malformed. Between 1024 and 1073741824.

SYNC_INLINE_FILES_DROP_TRUNCATEDtrueCut a payload body DIAL Core truncated at 4 MiB back to before the inline file the cut landed in.

SYNC_PAYLOAD_TABLEdial_usage_log_payloadSecond ingest target's table—the payload enrichment holding the five verbatim-content columns; its retention is SYNC_PAYLOAD_TTL_DAYS.
SYNC_PAYLOAD_MAPPING_FILEclasspath:mapping/dial-usage-log-payload.yamlSecond target's mapping file—match-all, shadowing the usage log one row per event_id. Drop this target to stop capturing raw content.
SYNC_PAYLOAD_TTL_DAYS— (keeps the live TTL)Payload retention in days, applied at startup. Unset preserves the live TTL (initially 90 days); -1 removes it. SYNC_USAGE_LOG_TTL_DAYS— (keeps the live TTL)Usage-log retention in days, applied at startup. Unset preserves the live TTL (initially one year); -1 removes it. Values 0, below -1, or below payload retention fail startup. Not applied (still validated, against the other only when both are set) when CLICKHOUSE_MIGRATIONS_ENABLED=false.
SYNC_RATE_TABLErate_analyticsThird ingest target's table.

Near-real-time poller​

Source: configuration reference.

VariableDefaultDescription
POLL_ENABLEDtrueMaster switch; true also when the property is absent. When off, ingestion proceeds only via the scheduled run.
POLL_CRON0 * * * * *Spring cron controlling how often a poll cycle runs.
POLL_OVERLAP5mHow far below the watermark to keep re-considering blobs, absorbing out-of-order writes and clock skew.
POLL_RESTART_LOOKBACK1hHow far back the watermark is set at startup, so a restart re-scans a bounded recent window.
POLL_PREVIOUS_DAY_GRACE1hHow long after UTC midnight to also scan the previous day's prefix. day mode only; ignored in band mode.

Ingestion and retention behavior​

The poller and daily reconciliation share the same blob layout and target mappings. Target dates and pipeline schedules use UTC. The service crons (SYNC_CRON, POLL_CRON, SYNC_RETRY_CRON, and AGGREGATE_TICK_CRON) fire in the JVM's default time zone, which is UTC only while the container's time zone is left unset. Disabling POLL_ENABLED leaves daily reconciliation and operator backfills available. The poller's watermark is in memory; restart lookback controls its recovery window. POLL_FINALIZATION_LAG must cover the longest request or stream; daily reconciliation recovers older arrivals.

Azure shared-key authentication needs both account name and key. Otherwise Azure uses DefaultAzureCredential, a blob endpoint, and a managed identity with Storage Blob Data Reader access. The storage account must have hierarchical namespace disabled. SAS tokens are unsupported. For S3, the endpoint must select the correct region; credentials can come from workload identity or an access-key pair.

sync.targets is a list of table/mapping pairs. An external YAML file replaces the list when adding or removing targets. At least one target is required. Each accepted record can produce a row in several targets. blob.overrides supplies additional jclouds properties when needed.

Warning

The shipped payload target stores raw content. Removing that target stops future capture; it does not delete stored content. Unset retention variables preserve live TTLs: new tables start with 90 days for payloads and one year for usage logs. Positive retention changes can expire existing rows. -1 removes the TTL; 0 is invalid.

Payload retention cannot exceed usage-log retention. Retention changes require ClickHouse migrations to be enabled. SYNC_REQUEST_BODY_MODE=delta stores only new chat messages; whole-with-path supports rollback from that format. The signed cursor keyring can be replaced with enrichment.cursor.keys in external YAML. Rotation adds a new key, selects it through active-key-id, and retains old verification keys while cursors remain in use. An empty cursor secret leaves cursor integrity unenforced.

Resource budgets​

Query and preview spill thresholds must remain below their memory ceilings; 0 disables spilling. Budget violations reject the request rather than sample or truncate query results. Pipeline statement timeouts must remain below the runner's ADAS_READ_TIMEOUT_MS. A group fetch can issue several statements, so its HTTP timeout also needs headroom for every heavy-column read. Aggregate scheduling runs in ADAS; SQL and LLM enrichment scheduling runs in the separate runner.
