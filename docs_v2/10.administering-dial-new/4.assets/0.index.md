# Artifacts

**Artifacts** are the shared building blocks that people and agents use at runtime in DIAL: skills,
prompts, files and conversations. Users create them in DIAL Chat or through the DIAL Core API, and publish
them to the organization. Published artifacts live in the **Public folder** of DIAL file storage and
appear in the **Artifacts** section of DIAL Admin. From there, other users can use them in Chat and
agents can use them in agentic workflows, according to each user's roles and permissions.

As an administrator, you see and govern the shared content of your organization: what was published,
where it lives, and who may use it.

## How artifacts get here

Everything a user creates in DIAL is stored in their private space and visible only to them. To make it
available to others, users **publish** it:

1. A user publishes a skill, prompt, conversation, file or other resource from DIAL Chat, or sends a
   publication request through the [Publications API](../../3.building-with-dial/7.working-with-dial-resources/2.publications-api.md).
   See [Sharing and publishing](../../6.chat-user-guide/6.sharing-and-publishing.md) for the user's view.
2. The request appears under **Governance > Approvals**. An administrator reviews it and approves or
   declines it. See [Review and approve publications](../7.publications-and-review.md).
3. After approval, the resource is moved to the Public folder and appears here. If the user chose a
   sub-folder, the access rules of that folder apply.
4. To withdraw it, the owner requests to unpublish it, or an administrator deletes it here.

Administrators can also create artifacts directly in the Public folder, or import them.

**Note**
> Publishing must be enabled in your deployment. See [Enable publications](../../4.operating-dial/4.configuration/8.enable-publications.md).

## What artifacts are

| Artifact | What it is | How it is used |
|----------|------------|----------------|
| **[Skills](6.skills.md)** | Reusable instructions that an agent picks up only when a task needs them. A skill is a `SKILL.md` file, with optional supporting files. | An agent decides when to use a skill. Attach skills to an agent, for example when building a Quick App, so the same procedure serves several agents. |
| **[Prompts](3.prompts.md)** | Reusable prompt templates with versions and variables. | Users insert them in Chat, and applications can read them through the DIAL Core API. |
| **[Files](5.files.md)** | Documents and data (PDF, CSV, images, JSON and others). | Models and applications reference them at runtime. |
| **[Conversations](4.conversations.md)** | Chat sessions that users published. | Available to the organization, and to administrators for review. |

**Applications** and **toolsets** that users publish are stored in the same way, in the Public folder.
You manage them in the **AI Gateway** section, together with the platform's own applications and
toolsets. See [Published applications](1.applications.md) and [Published toolsets](2.toolsets.md).

## Who can see what

The Artifacts screens show **only the Public folder**. Private content of individual users is never shown here.

- **Root folder:** visible to every authenticated DIAL user.
- **Sub-folders:** can carry **access rules** that match claims in the user's identity token, such as a
  role or a group. A user sees and uses a published artifact only if the rules of its folder, and of all
  its parent folders, allow it.
- **Protected resources:** prompts and files are protected resources and follow the DIAL access control model.

You manage the folders and their rules in **Governance > Folder Permissions**. See
[Folders Storage](7.folders-storage.md) and [Access control](../../2.understand-dial/4.security-and-governance/2.access-control-reference.md).

## What you can do here

- Browse the Public folder by artifact type and folder, with the author and update time of each artifact.
- Create, import, export, duplicate, move and delete artifacts, including whole folders.
- Open an artifact to edit its properties and content, or its raw JSON.
- Organize the Public folder in up to four levels of sub-folders.
- Set access rules that decide who can use each sub-folder, in **Folder Permissions**.
- Review incoming and withdrawn publications in **Approvals**, and track changes in the
  [audit log](../8.audit/1.activity-and-rollback.md).
