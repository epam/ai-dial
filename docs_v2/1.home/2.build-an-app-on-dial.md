# Build an app on DIAL

In this tutorial, you will run DIAL Core and DIAL Chat locally with Docker Compose and register a sample Custom App — the echo application — that repeats every prompt you send. By the end, you will have DIAL Chat open at `http://localhost:3000` talking to an application you registered yourself, and you will understand the three pieces that make an application a DIAL application: an HTTP endpoint, an entry in `config.json`, and a role that grants access to it. No cloud account or model API key is required.

## Prerequisites

- Docker Engine with Docker Compose v2.20.0 or higher. See the [Docker documentation](https://docs.docker.com/desktop/).
- Free TCP ports `3000` (DIAL Chat) and `8080` (DIAL Core) on your machine.

## What you'll build

This is not a full DIAL stack — it's the fastest way to run a custom application that exposes a chat completion endpoint alongside DIAL Core and DIAL Chat, so you can see how DIAL Core routes requests to it. Docker Compose starts DIAL Core, DIAL Chat, Redis, and chat themes, and runs the [echo application](https://github.com/epam/ai-dial/tree/main/dial-docker-compose/application/echo) next to them — a small Python service built with [DIAL SDK](https://github.com/epam/ai-dial-sdk) that repeats whatever you type. The echo application is the canonical "hello world" Custom App: it is a real, independently deployable service that DIAL Core routes requests to, not a wizard-generated agent.

## Step 1: Get the Docker Compose files

Clone the repository and change into the `application` sample:

```bash
git clone https://github.com/epam/ai-dial.git
cd ai-dial/dial-docker-compose/application
```

**Verify:** the directory contains `docker-compose.yml`, a `core/` directory, and an `echo/` directory.

## Step 2: Look at the application code

Open `echo/app.py`:

```python
from aidial_sdk import DIALApp
from aidial_sdk.chat_completion import ChatCompletion, Request, Response


class EchoApplication(ChatCompletion):
    async def chat_completion(
        self, request: Request, response: Response
    ) -> None:
        last_user_message = request.messages[-1]

        with response.create_single_choice() as choice:
            choice.append_content(last_user_message.content or "")


app = DIALApp()
app.add_chat_completion("echo", EchoApplication())
```

This is a complete DIAL Custom App: a class that subclasses `ChatCompletion` from DIAL SDK and implements one method, `chat_completion`, which reads the last message from `request.messages` and writes it back through `response`. `DIALApp` wraps it in a FastAPI application and `add_chat_completion("echo", ...)` exposes it under the deployment name `echo`.

**Verify:** you can point to the line that reads the incoming message and the line that writes the reply.

## Step 3: Launch DIAL

From the `application` directory, start the stack:

```bash
docker compose up
```

Docker pulls the DIAL Core, DIAL Chat, themes, and Redis images, then builds and starts the echo application from `echo/Dockerfile`. The first run takes a few minutes while images download.

**Verify:** the logs show the `core`, `chat`, and `echo` services started, with no errors.

## Step 4: Open DIAL Chat

Open `http://localhost:3000` in your browser.

**Verify:** the DIAL Chat interface loads.

## Step 5: Chat with the app you registered

The chat for **My Echo App** opens automatically. If it doesn't, open the Marketplace from the sidebar and select **My Echo App**.

Type a prompt and send it.

**Verify:** the echo application returns your message unchanged. You have registered and run your own application on DIAL.

## How it fits together

DIAL Core reads its configuration from `core/config.json`. The echo application is registered there as an application that DIAL Core exposes through the Unified API:

```json
"applications": {
    "echo": {
        "displayName": "My Echo App",
        "description": "Simple application that repeats user's message",
        "endpoint": "http://echo:5000/openai/deployments/echo/chat/completions"
    }
}
```

A `default` role grants access to the application, and an API key maps to that role:

```json
"keys": {
    "dial_api_key": {
        "project": "TEST-PROJECT",
        "role": "default"
    }
},
"roles": {
    "default": {
        "limits": {
            "echo": {}
        }
    }
}
```

Every model and application in DIAL is registered the same way — with an endpoint in `config.json` — and reached through the same Unified API. Access is layered on separately: the same API key can be granted a role that covers many models and applications, so you don't need a new key per app. That uniformity is what lets any app call any model, or any other app, without custom integration. The app you just ran was already written; [Getting started with DIAL SDK](../3.building-with-dial/1.apps/5.custom-apps/1.getting-started-sdk.md) walks through writing this same application from scratch.
