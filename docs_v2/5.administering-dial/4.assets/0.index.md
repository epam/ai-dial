# Assets

**Assets** is where administrators manage the content that lives in the **Public folder** of DIAL
file storage — the shared space that every authorized user can see, as opposed to the private folder
each user keeps to themselves. Content reaches the Public folder in one of two ways: an end user
**publishes** it (through a [publication request](../7.publications-and-review.md)), or an
administrator places it there directly.

Each asset type on this screen corresponds to a kind of object users create and share:

| Asset type | What it is |
|------------|------------|
| **[Applications](1.applications.md)** | Published applications — standalone, runner-based, or Code Apps — shared in the Public folder. |
| **[Toolsets](2.toolsets.md)** | Published Toolsets that connect to MCP servers and expose tools to applications. |
| **[Prompts](3.prompts.md)** | Reusable prompt templates, with versions and variables. |
| **[Conversations](4.conversations.md)** | Published chat sessions, available to administrators for review. |
| **[Files](5.files.md)** | Arbitrary binary or text files (PDF, CSV, images, …) that models and applications reference at runtime. |
| **[Skills](6.skills.md)** | Reusable agent capabilities that applications can invoke at runtime. |
| **[Folders Storage](7.folders-storage.md)** | The folder hierarchy itself, and the access rules that govern who can see each sub-folder. |

## Assets vs. Entities

Assets and [Entities](../2.entities/2.applications.md) both list Applications and Toolsets, but they
are not the same thing:

- **Entities** are the platform-level deployments an administrator configures directly in DIAL Admin.
  They are registered in DIAL Core and define what the platform *offers*.
- **Assets** are the copies of applications, toolsets, prompts, and files that users create and then
  **share into the Public folder**. They live in file storage, carry versions and an author, and are
  governed by folder access rules.

In short: Entities are what administrators deploy; Assets are what users publish.

## How it works

All asset types share one **folder model**. Objects are arranged in a hierarchy (up to four levels
deep), and access to each sub-folder is controlled by **access rules** evaluated against the
`claims` in a user's identity token. Because these rules are shared across every asset type, they are
documented once, under [Folders Storage](7.folders-storage.md). The effective rule for any object
combines the restrictions of all its parent folders up to the root.

## What you can do here

- Create, import, export, duplicate, and delete each asset type, and move objects between folders.
- Configure each asset in detail — properties, features, interceptors, dependencies, and raw JSON.
- Organize the Public folder hierarchy and set [access rules](7.folders-storage.md#access-rules) that
  decide who can see each sub-folder.

## Where Assets live in the Admin Panel

Assets are grouped under **Assets** in the DIAL Admin left menu. The [Catalog](../13.catalog/0.index.md)
section provides a unified browse view that combines these assets with platform-level entities.
