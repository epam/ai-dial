# Test suites

A test suite bundles a target deployment, metrics, a linked [dataset](2.datasets.md), and a request
template into a single evaluatable unit. Creating and configuring a test suite is the main setup step
before running an evaluation.

## Test suites grid

Open **Evaluation > Test Suites** to see all test suites.

<!-- SCREENSHOT NEEDED: test suites list grid -->

| Column | Description |
|--------|-------------|
| **Name** | Display name of the test suite. |
| **Type** | Evaluation type of the test suite. |
| **Creation date** | Timestamp when the test suite was created. |
| **Status** | Current state of the test suite. |
| **Actions** | Per-row actions: **Open in a new tab**, **Duplicate**, **Delete**. |

To create a test suite, click **Create**. A multi-step wizard guides you through target selection,
method configuration, and metric attachment.

## Test suite detail view

Click any test suite row to open its detail view. The detail view has five tabs.

### Properties

Basic information about the test suite.

<!-- SCREENSHOT NEEDED: test suite properties tab -->

| Field | Required | Editable | Description |
|-------|----------|----------|-------------|
| **Display name** | Yes | Yes | Name of the test suite displayed on the UI. |
| **Description** | No | Yes | Free-text summary of the test suite's purpose. |
| **Target deployment** | Yes | No | The model or application deployment this suite evaluates. Set during creation. |
| **Overall score** | No | Yes | Aggregation method for computing a single score across all metrics: **Weighted mean** (uses per-metric weights) or **Mean** (equal weight for all metrics). When configured, each run displays an overall score in its header. |
| **Overall score threshold** | No | Yes | Minimum passing score for the overall score. Runs that fall below this threshold are flagged, helping identify regressions quickly. |

### Method

The Method tab configures how requests are sent to the target deployment. It includes the request
template with variable expression references that map test-case fields into the prompt.

### Test cases

The Test Cases tab shows the test cases from the linked [dataset](2.datasets.md). The dataset
provides the test case schema and data; the test suite consumes them as evaluation inputs.

<!-- SCREENSHOT NEEDED: test cases tab with linked dataset -->

To link a dataset, select one from the dataset picker at the top of the Test Cases tab. Once linked,
the tab displays the dataset's test cases. If no dataset is linked, the test suite is **unbound** and
cannot run.

| Column | Description |
|--------|-------------|
| **Name** | Test case identifier. |
| **Enabled** | Whether the test case is included in runs. Disabled test cases are skipped. |
| **Custom fields** | Additional data columns defined by the dataset's test case schema. |

**Note**
> When a public dataset is attached, the test case data is read-only in the test suite view. Edit
> the test cases in the [dataset detail view](2.datasets.md#test-cases) instead.

Test case management actions (add, import, enable/disable, delete, schema editing) are available on
the dataset itself. See [Datasets — Manage test cases](2.datasets.md#manage-test-cases) and
[Datasets — Test case schema](2.datasets.md#test-case-schema).

#### Test case filter

You can define a filter expression to select a subset of test cases for evaluation. The filter uses a
query DSL to match test cases by their field values. When a filter is set, only matching test cases
are included when the test suite runs. This is useful for running focused evaluations on specific
categories or conditions within a large dataset.

### Metrics

The Metrics tab shows which metrics are attached to this test suite. Each metric has bindings that
map its inputs to test-case data or constant values.

<!-- SCREENSHOT NEEDED: metrics tab -->

#### Metric bindings

When you add a metric to a test suite, you configure its **input bindings** and **config bindings**.
Each binding maps a metric input parameter to one of three source types:

| Source type | Description |
|-------------|-------------|
| **Constant** | A fixed value (for example, a threshold of `0.7`). |
| **TestCase** | A column from the dataset's test case data (for example, `expected_output`). |
| **Response** | A column from the model's response (for example, `passages`). |

### Runs

The Runs tab lists all runs that have been executed for this test suite.

| Column | Description |
|--------|-------------|
| **Name** | Run name. |
| **Status** | Execution status: Pending, Running, Completed, or Failed. |
| **Started** | Timestamp when the run began. |
| **Ended** | Timestamp when the run finished. |
| **Actions** | Per-row actions: **Open in a new tab**, **Export**, **Delete**. |

To start a new run, click the **Run** button in the test suite header. A modal lets you configure
the run name and the number of iterations per test case.

## Delete a test suite

Open the context menu on any test suite row and select **Delete**. A confirmation dialog appears.
Deleting a test suite does not delete its completed runs or the linked dataset.
