# Evaluation overview

The Evaluation section of DIAL Admin lets administrators create test suites, define metrics, manage
reusable datasets, execute evaluation runs against deployed models and applications, and compare
results — all without leaving the Admin Panel. Use it to benchmark accuracy, measure response
quality, and track regression across releases.

## Concepts

| Concept | Description |
|---------|-------------|
| **Metric** | A reusable scoring function (for example, RAGAS Faithfulness or custom accuracy) that evaluates model responses against expected outputs. Metrics are defined once and attached to test suites. |
| **Dataset** | A reusable collection of test cases with a defined schema. Datasets are independent entities that can be shared across multiple test suites. Each dataset has its own test case schema and data, decoupled from any specific test suite. |
| **Test suite** | A bundle that ties together a target deployment, one or more metrics, a linked dataset, and a request template. Running a test suite produces a run. |
| **Test case** | A single input–expected-output pair inside a dataset. Test cases can carry custom schema fields (string, number, boolean, object, array, file). |
| **Run** | The result of executing a test suite. Each run records per-test-case metric scores, execution status, timing, and a link to Grafana traces. Completed runs can be compared side by side or exported to CSV. |
| **Playground** | An ad-hoc evaluation and health check tool that lets you send test requests to a deployment without creating a full test suite. Use it to verify a deployment is responding correctly. |

## How the sections map to your workflow

1. **Define metrics** — create or import the scoring functions your organization needs.
   See [Metrics](1.metrics.md).
2. **Create datasets** — build reusable collections of test cases with custom schemas.
   See [Datasets](2.datasets.md).
3. **Build test suites** — pick a target, link a dataset, attach metrics, and configure bindings.
   See [Test suites](3.test-suites.md).
4. **Execute and analyze runs** — launch a run, review per-test-case results, compare two runs, or
   export to CSV. See [Runs](4.runs.md).

## Where Evaluation fits in the Admin Panel

Evaluation appears as a top-level section in the sidebar with four sub-pages: **Metrics**,
**Datasets**, **Test Suites**, and **Runs**. Each sub-page has a list view (grid) and a detail view.
The section is available to all administrators; read-only users can view results but cannot create or
modify test suites, metrics, datasets, or runs.
