# Runs

A run is the result of executing a test suite. It records per-test-case metric scores, execution
status, timing, and optionally links to Grafana traces. Use the Runs section to review results,
compare two runs side by side, or export results to CSV.

## Runs grid

Open **Evaluation > Runs** to see all runs across all test suites.

<!-- SCREENSHOT NEEDED: runs list grid -->

| Column | Description |
|--------|-------------|
| **Name** | Run name. |
| **Test suite** | Name of the test suite that produced this run. |
| **Status** | Execution status: Pending, Running, Cancelling, Completed, Cancelled, or Failed. |
| **Started** | Timestamp when the run began. |
| **Ended** | Timestamp when the run finished. |
| **Actions** | Per-row actions: **Open in a new tab**, **Compare**, **Export**, **Delete**. |

## Run detail view

Click any run row to open its detail view.

<!-- SCREENSHOT NEEDED: run detail header -->

### Top bar controls

| Control | Description |
|---------|-------------|
| **Cancel** | Stop a running evaluation. The run transitions to **Cancelling** while in-flight requests complete, then to **Cancelled**. Results collected before cancellation are preserved. |
| **Delete** | Remove this run. |
| **Export** | Open the Export Run popup. See [Export to CSV](#export-to-csv). |
| **Import results** | Import evaluation results from a CSV file. Use this to bring in externally computed metrics or to restore previously exported data. |
| **Grafana** | Open the linked Grafana Explore view for this run's traces. Visible only when a Grafana URL is configured. |

### Analytics tab

The Analytics tab displays a grid of per-test-case results.

<!-- SCREENSHOT NEEDED: analytics tab grid -->

| Column group | Description |
|--------------|-------------|
| **Identification** | Test case name, overall score (if configured), and execution status icon. |
| **Execution** | Status, timing, iteration index, and execution result details. |
| **Metrics** | One column group per attached metric, showing score, evaluation time, and related values. |
| **Extracted** | Extracted response fields. |

Click a row to open a detail panel with metric score cards, evaluation latency, request/response
content, and resolved bindings. The detail panel uses a standardized layout across all metric types.

#### Overall score and aggregated metrics

The run detail header displays an **overall score** computed from all attached metrics using the
aggregation method configured on the test suite (weighted mean or equal-weight mean). If an overall
score threshold is set, the header indicates whether the run passed or failed.

Each test case row can also display its own **test case overall score** when configured, providing
per-row pass/fail status at a glance.

Below the overall score, **aggregated metric stat cards** summarize each metric across all test
cases. Each card shows the metric's mean score and evaluation latency.

#### Metric bindings in the detail panel

When viewing a row's detail panel, each metric group includes a collapsible **Metric bindings**
section. This section shows how each metric input was bound (Constant, TestCase, or Response) and
the resolved value, making it easy to verify the evaluation setup.

### Compare runs

You can compare two runs from the same test suite to identify regressions or improvements.

<!-- SCREENSHOT NEEDED: run comparison view -->

#### Start a comparison

Use one of the following methods:

- **From the run detail view**: Use the **Compare with** dropdown above the analytics grid. The
  dropdown lists all other completed runs from the same test suite. Select a run to enter compare
  mode.
- **From the runs grid**: Select a run's **Compare** action to open a comparison popup where you
  choose the second run.

#### Compare mode layout

In compare mode, the comparison view uses tabs to organize the analysis:

| Tab | Description |
|-----|-------------|
| **Summary** | High-level comparison of the two runs: overall scores, per-metric aggregated deltas, and a pass/fail summary. Use this tab for a quick regression check. |
| **Execution results** | Three-level column layout where each metric and execution column group splits into **Current** and **Compared** sub-groups, showing values from both runs side by side. Rows are joined by test case identity; unmatched test cases show a dash (`—`). |
| **Heatmap** | A visual matrix showing metric scores per test case. Cells are color-coded by score value. The heatmap includes an **Absolute values** view (raw scores) and a **Delta** view (score differences between runs). Use the metric filter to select which metrics appear. |

**Display controls**: A display panel provides toggles for the comparison view:

| Control | Description |
|---------|-------------|
| **Only matching** | When enabled, hides test cases that exist in only one of the two runs, showing only rows present in both. |
| **View differences only** | When enabled, the grid shows only rows with score differences. The diff counter recalculates based on visible columns. |
| **Hide highlights** | Disables row highlighting for differences. |
| **Column visibility** | Toggle visibility of column groups (Identification, Execution, individual metrics). |

**Row detail panel**: Click any row in the Execution results tab to open a bottom comparison panel showing side-by-side metric scores, score bars, request/response content, and diff highlighting with a diff count.

To exit compare mode, clear the **Compare with** dropdown selection. The grid reverts to its normal
layout.

## Export to CSV

You can export a run's results to a CSV file for offline analysis, reporting, or integration with
external tools.

1. Click the **Export** button in the run detail header, or select **Export** from the context menu
   in the runs list.
2. In the **Export Run** popup:

   | Section | Description |
   |---------|-------------|
   | **Columns accordion** | Select which columns to include. Columns are grouped by type (Identification, Data, Response, Metrics, Body). Use group-level checkboxes to select or deselect entire groups. Body columns (requestBody, responseBody, extractionWarnings) are unchecked by default. Within Metrics, columns are sub-grouped by metric name. |
   | **Preview accordion** | A live preview grid showing up to 10 rows with the currently selected columns. The preview updates instantly as you toggle columns. |

3. Click **Export CSV** to download the file.

**Note**
> In the exported CSV, column groups use `::` as a delimiter (for example,
> `Metrics::Faithfulness::score`).

**Note**
> The Export button is disabled while a run is still in progress.

## Playground

The Playground provides an ad-hoc evaluation and health check tool for deployments. Use it to send
test requests to a deployment and verify that it responds correctly, without creating a full test
suite or dataset.

<!-- SCREENSHOT NEEDED: playground view -->

To access the Playground, open **Evaluation > Playground** or use the Playground action from a
deployment's context menu.

## Delete a run

Open the context menu on any run row and select **Delete**, or click the **Delete** button in the
run detail header. A confirmation dialog appears before deletion.
