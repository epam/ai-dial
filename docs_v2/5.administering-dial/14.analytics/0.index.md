# Analytics [Preview]

The **Analytics** section of DIAL Admin turns the raw request stream that flows through DIAL Core into
queryable data, derived insights, and dashboards. Use it to understand usage and cost, enrich
conversation data with LLM-derived labels, run ad-hoc queries, and inspect individual sessions
end to end.

**Note**
> Analytics is a [Preview] feature. It is gated by the `ANALYTICS_ENABLED` environment variable and
> may change before general availability. All screens are backed by the **Analytics Data Access
> Service (ADAS)**.

## How Analytics fits together

Analytics is a small data pipeline you operate from the Admin panel:

```text
raw events          SOURCE tables        enrichment PIPELINES      ENRICHMENT tables
(dial_usage_log, ─► (landing tables  ─►  (per-row/-group          ─► (derived columns,
 conversations,      for raw data)        LLM or SQL transform)       e.g. session_insights)
 response_ratings)                   └─► aggregate PIPELINES ──────► rollup tables
                                                                         │
                                         QUERIES, DASHBOARDS, SESSIONS ◄─┘
                                         read the tables above
```

1. Raw events land in **source** [tables](2.tables.md) (for example the hop log `dial_usage_log`).
2. **Enrichment** [pipelines](3.pipelines.md) read a source table and run a transform — an **LLM** call
   or **SQL** — to write derived columns into an **enrichment** table (for example `session_insights`).
   **Aggregate** pipelines group and roll up data into summary tables.
3. [Queries](4.queries.md), [Dashboards](1.dashboards.md), and [Sessions](5.sessions.md) read the
   resulting tables to analyze, visualize, and inspect the data.

## Screens

| Screen | Description |
|--------|-------------|
| [Dashboards](1.dashboards.md) | System-wide usage, cost, latency, and activity dashboards, split by LLM, MCP, or Routes. |
| [Tables](2.tables.md) | The catalog of analytics tables. Create source and enrichment tables, define their column schema, manage access, and get connection snippets. |
| [Pipelines](3.pipelines.md) | Enrichment and aggregation workflows that derive data from source tables. An enrich pipeline with an LLM transform is what the product elsewhere calls an *evaluator*. |
| [Queries](4.queries.md) | Author and run read-only queries against analytics tables using a visual builder, JSON, SQL, or an AI assistant. Results render as a table or a chart. |
| [Sessions](5.sessions.md) | A read-only conversation-observability view. Browse sessions with usage, cost, feedback, and LLM-derived insights, and drill into per-call traces. |

## Configuration

Analytics is enabled through environment variables on the Admin Frontend:

| Variable | Description |
|----------|-------------|
| `ANALYTICS_ENABLED` | Master switch. Shows the **Analytics** section and gates every sub-screen. Required for all of the below. |
| `ANALYTICS_SESSIONS_ENABLED` | Shows the **Sessions** screen. Requires `ANALYTICS_ENABLED`. |
| `ANALYTICS_USAGE_ENABLED` | Serves the analytics **Dashboards** (usage) screen. Requires `ANALYTICS_ENABLED`. |
| `DIAL_QUERY_ASSISTANT_DEPLOYMENT` | Deployment name of the model that powers the **AI** assistant in the Query Builder. When empty, the AI tab is hidden. Requires `ANALYTICS_ENABLED`. |
