# Pipelines [Preview]

Navigate to **Analytics → Pipelines** to define the workflows that derive data from a source
[table](2.tables.md) into a **target** table on a schedule or when a group of rows is ready. There are
two kinds:

- **Enrich** — run a per-row or per-group **transform** (an **LLM** call or **SQL**) and write derived
  columns into an enrichment table. *An enrich pipeline with an LLM transform is what the product
  elsewhere calls an **evaluator*** — it is what populates `session_insights` and the **Insights** shown
  on the [Sessions](5.sessions.md) screen.
- **Aggregate** — group a source table and compute measures, writing a rollup table.

## Pipelines grid

| Column | Description |
|--------|-------------|
| **Name** | Pipeline identifier. |
| **Kind** | `enrich` or `aggregate`. |
| **Target** | The table the pipeline writes to. |
| **Inputs** | The source table(s) the pipeline reads. |
| **Trigger** | What runs the pipeline: `schedule` or `group`. |
| **Transform** | For enrich pipelines, the transform type: `LLM` or `SQL`. |
| **Enabled** | Whether the pipeline is enabled. |
| **Runtime** | Live runtime status (running, paused, held, over-budget, backpressured, or not tracked). |
| **Generation** | Increments each time the pipeline's definition is re-declared. |
| **Updated at** | Timestamp of the last change. |

Use **Create pipeline** (top-right) to add one.

## Detail view

Click any pipeline to open its detail view. The header has a **JSON Editor** toggle, an
**Enable/Disable** control, and **Delete**. The tab strip is **Properties**, **Runtime**, and **Audit**.

### Properties

The Properties tab shows the full declaration. Common fields:

| Field | Description |
|-------|-------------|
| **Grain key** / **Version column** / **Generation** | Read-only identity and versioning of the pipeline. |
| **Source** | The source table the pipeline reads (follows the target's source, or a pinned input). |
| **Target** | The table the pipeline writes to. |
| **Filter** | A SQL predicate that selects which rows the pipeline considers. Empty means every row. |
| **Trigger** | **Schedule** (a cron expression, with presets such as every 5 minutes, hourly, or daily at midnight) or **Group** (see below). |

For a **Group** trigger, you also configure:

| Field | Description |
|-------|-------------|
| **Group by** | The column(s) that define a group (for example `chat_id`). |
| **A group is ready when** | Conditions that mark a group ready to process — idle time, maximum staleness, or a cost ceiling. |
| **Member selection** | Which rows of a ready group to include, with an order and a row limit. |

For an **Enrich** pipeline, the **Transform** section defines the derivation:

| Field | Description |
|-------|-------------|
| **Type** | `LLM` or `SQL`. |
| **Model** | *(LLM)* The model that runs the transform. |
| **Model parameters** | *(LLM)* Key-value knobs passed to the model, such as `max_tokens` and `temperature`. |
| **Request template** | *(LLM)* The prompt sent to the model. Supports placeholder tokens — including `{{members}}`, `{{members_included}}`, `{{members_omitted}}`, `{{members_truncated}}`, and `{{members_notice}}` for group triggers. |
| **Inputs** | Bind source columns to variables used by the transform. |
| **Outputs** | Map the transform's results to the target table's columns. |

An **Aggregate** pipeline instead defines **Group keys** (plain columns, or a time truncation by hour,
day, week, or month) and **Measures** (named aggregate functions over a column, with an optional filter
and distinct flag).

An **Advanced** accordion exposes throughput controls: scan frequency, rows per scan, rows per call,
rate limit (RPM), and sample fraction.

### Runtime

The Runtime tab shows the pipeline's live operational state and lets operators keep it healthy:

- **Runtime status** — running, paused, held, over-budget, or backpressured, with the pause origin
  (operator or circuit breaker).
- **Pause / resume** — pause a pipeline (a banner appears while paused) and resume it.
- **Failures** — a dead-letter queue of rows that failed at a processing stage (input mapping, the model
  call, validation, output mapping, or the upsert), with the ability to **requeue** them.
- **Groups** — for group-triggered pipelines, the readiness of each group and its evaluation runs.

### Audit

The Audit tab records configuration changes to the pipeline (available when the Admin API is enabled).

## Create a pipeline

1. Click **Create pipeline**.
2. Choose the **Kind** (Enrich or Aggregate) and the **Target** table.
3. The pipeline is created; open it to configure its source, filter, trigger, and transform (or group
   keys and measures), then **Enable** it.

**Tip**
> Use the **JSON Editor** toggle to view or edit the entire pipeline declaration at once.
