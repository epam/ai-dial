# Aliases

An **alias** is a deployment of its own, with its own name, catalog entry, and `userRoles`. It forwards every call to a target deployment: a model, an application, or a toolset. A caller who may use the alias may call the target through it, even without rights on the target. The alias does not let the caller read the target's definition or credentials. Only admins manage aliases.

## Where aliases are defined

| Source | Location |
|---|---|
| Config file | `aliases.<name>` |
| Configuration API | `/v1/aliases/public/<name>` |

An alias shares the namespace of models, applications, toolsets, and interceptors: a config file with an alias and another deployment of the same name does not load. Aliases have no version of their own, so put the version in the name, for example `assistant-v1`. The fields are declared in [Alias.java](https://github.com/epam/ai-dial-core/blob/0.50.7/config/src/main/java/com/epam/aidial/core/config/Alias.java), and the config key in [Config.java](https://github.com/epam/ai-dial-core/blob/0.50.7/config/src/main/java/com/epam/aidial/core/config/Config.java#L42).

## Fields

| Field | Description |
|---|---|
| `target.path` | Required. `models/<name>`, `applications/<name>`, or `toolsets/<name>` for a deployment of the config, or `applications/<bucket>/<path>` or `toolsets/<bucket>/<path>` for a resource. The target cannot be another alias. |
| `presentAs` | The type the alias is listed and called as: `model`, `application`, or `toolset`. Defaults to the type of the target. A model or an application can be presented as either; a toolset only as a toolset; an application can be presented as a toolset when it has `mcp`. |
| `userRoles` | The roles that may use the alias. When unset, the alias takes the target's roles, or read access to a resource target. An alias never opens its target to more callers than the admin listed. |
| `displayName`, `description`, `iconUrl`, `intro`, `descriptionKeywords` | Shown in listings. When unset, the target's values are shown. |
| `displayVersion`, `author`, `createdAt`, `updatedAt`, `catalogSchemaId`, `catalogProperties` | Shown in listings. They describe the alias's own entry and never fall back to the target's. |

Other deployment fields, such as `endpoint`, `interfaces`, `features`, and `pricing`, are ignored on an alias: listings show the target's.

A config whose alias has no `target.path`, points to an alias, or has a `presentAs` that does not fit a config target does not load. A config target that does not exist only logs a warning: calls of the alias answer `503`, and listings leave it out. `GET /v1/admin/health/config` reports it with the reason `alias_target_missing`, or `alias_target_incompatible` when the target no longer fits the alias's type.

```json
{
  "aliases": {
    "assistant-v1": {
      "displayName": "Assistant",
      "description": "General-purpose assistant.",
      "userRoles": ["default-user"],
      "target": { "path": "models/gpt-4-internal" }
    }
  }
}
```

## How a call works

An alias is called by its name, through the endpoints of its type, such as `/openai/deployments/<alias>/chat/completions`, `/openai/v1/responses`, or `/v1/toolset/<alias>/mcp`. Core calls the target in a second pass over its own HTTP address, which is `backgroundJob.localBaseUrl`; set it when the server port is not reachable on `localhost`. See [Background jobs](2.settings/12.background-jobs.md). The second pass:

- records `execution_path` as `[alias, target]`, with one span and one analytics row per pass;
- checks and charges limits and cost under the **target's** name, so several aliases of one model share its quota. A role that reaches a model only through an alias needs its limit defined under the model's name.
- runs the target's interceptors and the global interceptors once;
- does not forward the caller's `Authorization` header, so a target with `forwardAuthToken` does not receive it.

## Aliases in public storage

Admins can also create aliases at run time (preview). A stored alias is called and listed by its url `aliases/public/<name>`; the bare name does not reach it.

| Method and path | What it does |
|---|---|
| `PUT /v1/aliases/public/<name>` | Create or replace the alias. |
| `GET /v1/aliases/public/<name>` | Read the definition. |
| `DELETE /v1/aliases/public/<name>` | Delete the alias; the target is not touched. |
| `GET /v1/metadata/aliases/public/` | List the stored aliases. |

Every method is for admins only. Only the `public` bucket is supported, and a name may hold letters, digits, `.`, `_`, and `-`. The body accepts `target`, `presentAs`, `userRoles`, and the display fields; any other field answers `400`. The target must be a config deployment or a resource in the `public` bucket. A stored alias cannot be shared, published, copied, or moved, and it cannot be written through `/v1/admin/validate` or `/v1/admin/apply`. The [admin system export](1.configuration-api.md) includes stored aliases with the rest of the public bucket.

The routes are registered in [ConfigResourceController.java](https://github.com/epam/ai-dial-core/blob/0.50.7/server/src/main/java/com/epam/aidial/core/server/controller/ConfigResourceController.java#L1019).
