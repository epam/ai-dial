# Architecture

This section explains how DIAL is built: its services, how requests move through them, what you deploy and operate, and where the limits are. It is for architects assessing DIAL for their organization. It assumes you have read [What is DIAL](../1.what-is-dial.md); installation steps are in [Operating DIAL](../../4.operating-dial/2.cloud-deployment/0.index.md).

## In this section

- [Architecture highlights](./1.architecture-highlights.md) — the services around DIAL Core, what each is responsible for, and where your own services plug in.
- [Request flow](./2.request-flow.md) — the runtime paths for models, applications, MCP Toolsets, and routes, and how interceptors process them.
- [Deployment profiles](./3.deployment-profiles.md) — which services to adopt for the capabilities you need, and the infrastructure and ownership behind each choice.
- [State and data lifecycle](./4.state-and-data-lifecycle.md) — how DIAL Core separates service instances from stored resources, for planning persistence, retention, and recovery.
- [Reliability and performance](./5.reliability-and-performance.md) — failure dependencies, failover boundaries, and workload sizing.
- [Application hosting and lifecycle](./6.application-server.md) — who hosts and runs each application type, from authoring to operation.
- [AI API overview](./7.ai-api-overview.md) — the Unified API, the other supported AI APIs, passthrough and translation, and multimodal models.
- [Trade-offs and limitations](./8.trade-offs-and-limitations.md) — the architectural trade-offs, the limitations that can rule out a deployment, and the cost boundary.
- [DIAL Stack](./9.dial-stack.md) — reference for the technologies and infrastructure behind DIAL.

## Suggested reading path

The pages build on each other. Read [Architecture highlights](./1.architecture-highlights.md) and [Request flow](./2.request-flow.md) first, then [Deployment profiles](./3.deployment-profiles.md) before [State and data lifecycle](./4.state-and-data-lifecycle.md) and [Reliability and performance](./5.reliability-and-performance.md). The remaining pages can be read in any order.

To go straight to a specific decision, use the table in [Evaluate your architecture](./1.architecture-highlights.md#evaluate-your-architecture).
