# DIAL File Manager 0.4.0

File Manager 0.4.0 moves to UI Kit 0.16 and Tailwind CSS v4, adds per-item action restrictions and custom item icons, and reports rejected uploads. This page summarizes the release for frontend developers who plan an upgrade. There are no patch releases.

## 0.4.0

Released 2026-11-04. [Release notes](https://github.com/epam/ai-dial-react-file-manager/releases/tag/0.4.0)

**Breaking**

- `styles.css` is built with Tailwind CSS v4 and sits in the kit's `ui.base` and `ui.utilities` cascade layers. A host's unlayered CSS and the kit's `dial-*` classes now win over a File Manager utility that sets the same property, and `hover:` applies only on devices that can hover. Class names, theme tokens, and props are unchanged. Re-check host overrides that relied on the old cascade order, and follow the UI Kit [Tailwind v4 migration guide](https://github.com/epam/ai-dial-ui-kit/blob/0.16.0/migration-guides/0.16.0/tailwind-v4-stylesheet.md).
- The `@epam/ai-dial-ui-kit` peer range is raised from `^0.15.0` to `^0.16.0`. Install the stable 0.16 kit and keep loading its `styles.css` with this package's.

**Added**

- `DialFoldersTree` follows the 2.0 tree item: the caret only expands or collapses, and clicking a row selects it. `selectOnCaretClick` now defaults to `false` in `DialFoldersTree` and `DialFileManager`; pass `true` to keep the old behavior.
- `getItemActionRestriction(file, action)` on `DialFileManager` disables Move, Download, Rename, or Delete for single items and shows the returned reason.
- Custom item icons through `DialFoldersTree.getItemIcon`, `treeOptions.getItemIcon`, and `gridOptions.getItemIcon`.
- `toolbarOptions.additionalButtons` renders host controls in the header toolbar before the Add button.
- `hideHiddenFilesLabel` on `DialDestinationFolderPopup` and `destinationFolderPopupOptions`, a localizable label for the hidden-files toggle.

**Fixed**

- Rejected uploads are no longer silent. An oversized or unsupported file, a dropped folder, or a failed `onValidateUpload` shows an error above the grid. A host can handle the new `onUploadValidationError` instead. Only the oversized files in a selection are rejected, not the whole batch.
- The "more" menu buttons in the grid and `DialFoldersTree` have an accessible name, set through `gridOptions.rowActionsLabel` and `contextMenuButtonLabel` and defaulting to "More actions".
- Move can no longer nest a folder inside itself. The tooltip is set by `destinationFolderPopupOptions.movedIntoItselfTooltip`.
- Cmd or Ctrl with A, C, V, X, or Z in the rename and new-folder inputs acts on the input text instead of selecting every grid row.
- A dot-prefixed new folder name runs the duplicate-name check and `onCreateFolderValidate`, so reserved names such as `.dial_folder` can no longer be confirmed.
- `treeOptions.header` is drawn above the compact navigation card; `header: null` still hides it.
- `DialFoldersTree` file rows keep a caret-width slot with `showFiles`, so icons on the same level line up.
- Section chips are semibold in every state, and tree rows use the same hover and selected backgrounds as grid rows.
- Shadow tokens match the design and the kit. A theme that set `--shadow-xs-2` should note that it is no longer read.

**Other**

- `styles.css` shrinks from about 58 KB to 17 KB because it no longer repeats the kit's utilities. The kit's `styles.css` must still be loaded with it.
- Security-related upgrades of development dependencies. None of them reach the consumer runtime.
