# What are Quick Apps

Quick Apps are a no-code orchestrator for building AI workflows on DIAL. They combine a language model, system instructions, and tools into a complete application — without writing code. Quick Apps are conceptually similar to OpenAI's GPTs.

This page explains how Quick Apps work, what tools they can use, and how they fit into the DIAL app ecosystem.

## How Quick Apps work

A Quick App is built around three elements:

- **Orchestrator** — the language model (with its parameters) that processes user messages, decides when to call tools, and composes the final response.
- **Instructions** — the orchestrator's system prompt, which guides the model's behavior, tone, and scope.
- **Tools** — external capabilities the orchestrator can invoke: other DIAL apps and models, REST APIs, MCP servers, and predefined tools.

When a user sends a message, the orchestrator receives the system instructions and the conversation history. If it determines that a tool is needed, it calls the tool, receives the result, and incorporates it into the response. This agent loop can repeat multiple times within a single request, up to `max_iterations` operations (default 15).

Because Quick Apps follow the Unified API, they are indistinguishable from other DIAL apps to callers. A Quick App can be called by other apps, used as a tool in another Quick App, or accessed through DIAL Chat and the API.

## Available tools

Quick Apps connect to capabilities through typed **toolsets**. Each entry in the `tool_sets` array declares a `type`:

| Toolset type | What it does | Example |
|---|---|---|
| **Predefined** (`predefined`) | Ready-made tools and toolsets selected by `template_name` — web search, image generation, Python interpreter, RAG (`dial_rag`), and more | Add `dial_rag` to answer questions from uploaded documents |
| **DIAL deployment** (`dial-deployment`) | Calls other DIAL models or applications as tools | Route complex questions to a specialized app |
| **REST API** (`rest-api`) | Calls external REST APIs with configurable authentication (API key, basic, bearer, OAuth 2.0) | A weather assistant that calls the Open-Meteo API |
| **External MCP** (`mcp`) | Connects to external [MCP servers](./quick-app-2/toolsets/index) over SSE or streamable HTTP | Access a database through an MCP server |
| **DIAL-managed MCP** (`dial-app`) | Connects to an MCP toolset hosted as a DIAL deployment | Reuse a shared, DIAL-hosted toolset |

Tools can be combined freely — a single Quick App can use several toolsets at once. Retrieval-augmented generation (RAG) is not a built-in feature: add the predefined `dial_rag` tool to ground answers in documents.

## Creating Quick Apps

Quick Apps can be created through three methods:

| Method | Best for | Guide |
|---|---|---|
| **UI wizard in DIAL Chat** | End users and rapid prototyping. Visual form for the model, instructions, and tools — no config files needed. | [Create in DIAL Chat](./quick-app-2/create-via-ui) |
| **API** | Developers building automation, CI/CD pipelines, or programmatic app management. | [Create via API](./quick-app-2/create-via-api) |
| **config.json** | DevOps teams provisioning apps as infrastructure-as-code. Apps are available when DIAL Core starts. | [Create via config.json](./quick-app-2/create-via-config) |

## Configuration model

A Quick App is defined by the application type schema ID `https://mydial.epam.com/custom_application_schemas/quickapps2`. Its top-level properties are:

| Property | Required | Description |
|---|---|---|
| `orchestrator` | Yes | The orchestrator deployment (model + parameters), its system prompt, and the agent-loop iteration limit. |
| `contexts` | Yes | Array of document contexts that ground the orchestrator (file or user-defined). May be empty. |
| `tool_sets` | Yes | Array of toolset configurations. May be empty. |
| `conversation_starters` | No | Suggested starting prompts shown to users. |

Minimal valid Quick App 2.0 configuration:

```json
{
  "orchestrator": {
    "deployment": {
      "deployment_id": "gpt-4o-mini",
      "parameters": { "temperature": 0.5 }
    },
    "system_prompt": {
      "type": "custom",
      "variables": {},
      "content": "You are a helpful assistant."
    }
  },
  "contexts": [],
  "tool_sets": []
}
```

The orchestrator drives the agent loop for up to `max_iterations` operations per turn (default 15); a single operation may issue several tool calls. Toolsets can combine REST APIs, DIAL deployments, external MCP servers, DIAL-managed MCP, and predefined templates.

## Sharing and access

Quick Apps follow the standard DIAL sharing model:

- **Private by default** — a new Quick App is visible only to its creator.
- **Shareable** — grant READ or WRITE access to specific users. WRITE access enables real-time co-editing.
- **Publishable** — submit the app to the Marketplace for broader access. Publishing requires administrator approval.

## When Quick Apps are the right choice

Quick Apps work well when:

- You want to compose a workflow from existing models, apps, and APIs without writing code.
- You need rapid prototyping — create, test, and iterate in minutes.
- You want document grounding with minimal setup, using the predefined RAG tool.
- You need tool orchestration where the model decides when and how to use tools.
- End users should be able to create their own customized assistants.

For use cases that require full network access, custom dependencies, or your own infrastructure, consider a [Custom App](../custom-apps/index) instead. For quick Python prototyping without infrastructure concerns, consider a [Code App](../code-apps/index).
