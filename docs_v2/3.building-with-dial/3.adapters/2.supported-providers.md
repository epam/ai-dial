# Supported providers

DIAL ships three model adapters that translate provider-specific APIs into the Unified API. This page lists the providers each adapter supports, the model families available through each, and the authentication methods required.

## Adapter-provider mapping

| Provider | Adapter | Authentication |
|---|---|---|
| Azure OpenAI | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key or Azure AD token |
| OpenAI Platform | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key |
| Azure AI Foundry | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key or Azure AD token |
| Mistral | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key |
| Anthropic API | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key |
| Databricks | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key |
| Alibaba Cloud Model Studio | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | API key |
| vLLM / Ollama | [OpenAI Adapter](https://github.com/epam/ai-dial-adapter-openai) | None (local) |
| AWS Bedrock | [Bedrock Adapter](https://github.com/epam/ai-dial-adapter-bedrock) | AWS IAM credentials |
| Google Vertex AI | [Vertex AI Adapter](https://github.com/epam/ai-dial-adapter-vertexai) | GCP service account or ADC |

Anthropic Claude appears three times in this table, because it is reachable three ways: through the Anthropic Messages API, through AWS Bedrock, and through Google Vertex AI. Pick the row that matches where you buy the capacity. Claude request and response semantics are the same in each case: both adapters delegate them to the shared [aidial-adapter-anthropic](https://github.com/epam/ai-dial-adapter-anthropic) package, which documents them.

## Models by adapter

### OpenAI Adapter

The OpenAI Adapter (v0.43.3) selects behaviour from the **upstream API** a deployment points at, not from the model's name. So it is listed here by upstream API rather than by model: any deployment that matches none of the specialised categories below is treated as OpenAI-compatible text-to-text chat completion or text embeddings.

| Upstream API | Reachable through |
|---|---|
| Chat Completions | Azure OpenAI, OpenAI Platform, Azure AI Foundry, Mistral, Databricks, vLLM, Alibaba Cloud Model Studio, Amazon Bedrock |
| Responses | Azure OpenAI, OpenAI Platform, Amazon Bedrock, Alibaba Cloud Model Studio |
| Anthropic Messages | Claude on Azure AI Foundry, the Anthropic API, and other providers of the same API |
| Embeddings | Azure OpenAI, OpenAI Platform, vLLM, Azure multimodal embeddings |
| Image generation | `dall-e-3`, `gpt-image-1` |
| Video | `sora`, `sora-2` |
| Text to speech | `tts`, `tts-hd`, `gpt-4o-mini-tts` |
| Speech to text | `whisper`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`, Qwen3-ASR on vLLM |

GPT-4 Vision is deprecated — those models were retired by both Azure OpenAI and the OpenAI Platform.

### Bedrock Adapter

The Bedrock Adapter (v0.43.3) supports AWS Bedrock through both the Runtime API and Converse API.

| Vendor | Model families |
|---|---|
| Anthropic | Claude 5 (Opus, Sonnet, Fable), Claude 4.8 Opus, Claude 4.7 Opus, Claude 4.6 (Opus, Sonnet), Claude 4.5 (Sonnet, Haiku), Claude 4.1 Opus, Claude 4 (Opus, Sonnet), Claude 3.7 Sonnet, Claude 3.5 (Sonnet, Haiku), Claude 3 (Opus, Sonnet, Haiku) |
| Meta | Llama 4 (Scout, Maverick), Llama 3.3, Llama 3.2, Llama 3.1, Llama 3 |
| DeepSeek | R1 |
| MiniMax | M2.5 |
| Stability AI | SD 3.5 Large, Stable Image Ultra/Core |
| Amazon | Nova Pro, Nova Lite, Nova Micro |
| AI21 Labs | Jamba 1.5 (Large, Mini) |
| Cohere | Command R, Command R+ |
| Embeddings | Titan Multimodal G1, Titan Text V2, Titan Embeddings G1, Cohere Embed (English, Multilingual) |

Each chat model is also addressable through cross-region inference by prefixing its deployment id with a region — for example `us.anthropic.claude-sonnet-4-5-20250929-v1:0`.

### Vertex AI Adapter

The Vertex AI Adapter (v0.39.1) supports Google Vertex AI, Google AI Platform, and Google Search grounding for Gemini models.

| Category | Model families |
|---|---|
| Gemini | 3.5, 3.1, 3, 2.5, 2.0 |
| Imagen | Imagen 4, Imagen 3, Imagen 2 |
| Veo | Veo 3.1, Veo 3.0 |
| Partner models | Anthropic Claude, Mistral Medium 3, Mistral Small, Codestral |
| Embeddings | gemini-embedding-001, text-embedding-004/005, text-multilingual-embedding-002, multimodalembedding@001 |

## OpenAI-compatible models

Any model that exposes an OpenAI-compatible API can be accessed through the OpenAI Adapter. This includes self-hosted models served by vLLM, Ollama, TGI, and similar inference servers. Configure the adapter's endpoint to point to the model server and use the appropriate deployment environment variables.

For adapter environment variable reference, see [Adapter configuration](../../4.operating-dial/4.configuration/3.adapter-configuration.md).

## How to enable a model

Models are registered as deployments in DIAL Core through one of two methods:

- **DIAL Core config.json** — add a model entry with the adapter endpoint and upstream configuration. See the [config.json models reference](../../4.operating-dial/4.configuration/1.core/2.config-json/1.models.md).
- **DIAL Admin** — add models through the administration UI. See [Admin Panel: Models](../../5.administering-dial/2.entities/1.models.md).

## Adding an unsupported provider

Organizations that need to integrate a provider not covered by the official adapters can build a custom adapter using [DIAL SDK](https://github.com/epam/ai-dial-sdk). The [Tutorial: custom adapter](1.tutorial-custom-adapter.md) walks through the process from project setup to deployment.
