# DIAL Deep Research API and request flow

Deep Research **0.4.0** serves DIAL Chat Completions, a property-schema endpoint, and an SDK health check. This reference is for platform engineers integrating clients or diagnosing requests. It assumes the [backend and application instance](1.configuration/0.index.md) are configured in Core.

## Endpoints

Clients call DIAL Core with the **application instance ID**, for example `research-example`. Core routes the request to the backend's fixed deployment, `deep-research`.

| Method | Backend path | Purpose |
|---|---|---|
| `POST` | `/openai/deployments/deep-research/chat/completions` | Main preparation and research workflow |
| `POST` | `/openai/deployments/deep-research/rate` | SDK rating route, registered with every chat completion; the backend does not override its no-op handler |
| `GET` | `/v1/configuration-support/application-schema` | Property JSON schema that Core downloads through `dial:applicationTypeSchemaEndpoint` |
| `GET` | `/health` | SDK liveness response: `{"status":"ok"}` |
| `POST` | `/openai/deployments/deep-research-playground/chat/completions` | Tool-calling agent, only when `ENABLE_PLAYGROUND_CHANNEL=true` |
| `POST` | `/openai/deployments/deep-research-annotations-demo/chat/completions` | Fixed report citing two attached PDFs, only when `ENABLE_ANNOTATIONS_DEMO=true` |

The backend [registers these deployments and the schema handler](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/factory.py#L37-L84). Its locked dependency is [DIAL SDK 0.32.0](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/poetry.lock#L21-L25). The SDK supplies the [completion and rate routes](https://github.com/epam/ai-dial-sdk/blob/0.32.0/aidial_sdk/application.py#L135-L157), [health route](https://github.com/epam/ai-dial-sdk/blob/0.32.0/aidial_sdk/application.py#L98-L100), and [health response](https://github.com/epam/ai-dial-sdk/blob/0.32.0/aidial_sdk/application.py#L307-L309).

The health handler returns a fixed response. It does not check Core, model, or MCP connectivity. The schema handler returns property definitions without the root application-type identity. Core downloads the schema the first time it resolves the type, merges it with the registration, and caches the result; see [ApplicationSchemaService](https://github.com/epam/ai-dial-core/blob/0.49.4/server/src/main/java/com/epam/aidial/core/server/service/ApplicationSchemaService.java#L183-L212).

## Client request

The first turn calls the instance through Core:

```bash
curl --no-buffer 'https://<DIAL_HOST>/openai/deployments/research-example/chat/completions?api-version=2025-04-01-preview' \
  -H 'api-key: <DIAL_API_KEY>' \
  -H 'Content-Type: application/json' \
  --data '{
    "messages": [
      {
        "role": "user",
        "content": "Compare the main risks described in the last two quarterly reports."
      }
    ],
    "stream": true
  }'
```

The model can ask clarification questions and propose a plan before research begins. Follow-up requests include the prior conversation messages, preserving each assistant message's `custom_content.state`. Approval arrives as another user turn; it is not a separate HTTP endpoint.

The backend loads and validates application properties, restores preparation state, fetches source descriptions, and runs preparation. Once the plan is approved and research starts, it runs the research graph in that same request. Source: [turn coordinator](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/completion.py#L50-L108) and [start-research tool](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/preparation/tools.py#L224-L242).

## Progress and report delivery

With `stream=true`, the SDK returns `text/event-stream`. Heartbeat comments arrive at the configured interval, default five seconds. With `stream=false`, the SDK collects the result into a JSON response. Source: [SDK response handling](https://github.com/epam/ai-dial-sdk/blob/0.32.0/aidial_sdk/application.py#L267-L293).

Research work and reviews appear as DIAL stages. Report drafts are withheld while reviews can still revise them; the final report is appended once after the graph finishes. The report is therefore not delivered token by token during research. Source: [research runner contract](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/research/runner.py#L1-L21).

Citation metadata is emitted in `custom_content.annotations` after report content. A client must preserve and render those annotations to display citation pills. Document citations depend on the configured file-sharing tool and metadata resource; dataset and query citations depend on StatGPT metadata. Sources: [annotation payload](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/utils/dial_annotations.py#L24-L52) and [citation delivery](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/research/runner.py#L598-L643).

Citation conversion or References construction can fail independently of the research turn. The delivery code logs these failures and retains the available report content. Missing citation links do not prove that retrieval failed; source configuration and citation-resolution logs distinguish the cases.

## Conversation state

The backend stores two internal values in each assistant message's `custom_content.state`:

| Value | Purpose |
|---|---|
| `messages` | Serialized research/preparation history, including tool messages |
| `preparation` | Current query, clarification, plan, approval, and research-start status |

Clients carry the returned state forward unchanged with the corresponding assistant message. It is not a replacement for the visible conversation text. Preparation state comes from the latest assistant message with valid state; a fresh state is used only when no message has one. Missing usable message state falls back to visible assistant content. Sources: [state and history serialization](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/history.py#L58-L136) and [preparation-state restoration](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/history.py#L139-L172).

Once the restored state has `research_started=true`, another turn raises a conflict asking for a new conversation. The service does not provide a separate resume/job API for a completed research. See [the coordinator check](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/completion.py#L62-L66) and [conflict condition](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/error_resolution.py#L160-L167).

## Errors

Turn failures use DIAL protocol errors, with user-facing text and an eight-character error reference for log correlation. A failure can produce a non-success HTTP response or an in-stream error chunk after streaming has begun. A `200` streaming response alone is not proof of success. Source: [error delivery](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/error_resolution.py#L511-L555).

| Condition | Result |
|---|---|
| Invalid application properties | Application-not-configured protocol error; administrators must correct the instance properties |
| Research already started in this conversation | Conflict condition, `409` on the HTTP error path |
| Research graph exceeds its step budget | Protocol error instructing the user to narrow the request and start a new conversation |
| Upstream authentication, permission, or missing deployment/resource | User-facing service/model error; check the backend's correlated log record |
| Reached research iteration or report version limit | The graph proceeds to report delivery according to its budget rules; distinct from the graph-step failure limit |

Sources: [property validation](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/properties.py#L20-L37), [internal conditions](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/error_resolution.py#L121-L167), and [graph routing](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/research/graph.py#L148-L175).
