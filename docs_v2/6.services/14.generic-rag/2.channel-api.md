# Generic RAG channel API

The channel API manages the documents of a Generic RAG application and searches them. The frontend uses it, and scripts and applications can too. This reference lists every endpoint of backend 0.3.3. It is for developers and administrators who manage an application's documents and know the [channel configuration](1.channel-configuration.md).

## Calling the API

The API is an [application route](../1.core/1.configuration/10.routes.md) of the type. Send requests to DIAL Core, at `/v1/deployments/<application>/route/channel/...`, with your DIAL credentials. DIAL Core forwards them to the backend's `/channel/...` with a per-request key and the application's ID.

`<application>` is the application's ID: its name in the DIAL Core configuration, or `applications/<bucket>/<name>` for an application in a bucket. The backend serves an interactive description of the API at `/docs`, which DIAL Core doesn't route.

```bash
curl -X POST "https://<DIAL_HOST>/v1/deployments/<APPLICATION_ID>/route/channel/documents?folder=reports" \
  -H "Api-Key: <DIAL_API_KEY>" \
  -F "attachment=@annual-2025.pdf;type=application/pdf" \
  -F 'metadata={"category": "annual-report", "published_on": "2025-03-01"}'
```

## Documents

A document is returned as this object:

| Field | Description |
|---|---|
| `id` | The document's ID in the channel, a number from `1` |
| `url` | The file in the application's bucket |
| `display_name` | The folder and the original file name, such as `reports/annual-2025.pdf` |
| `mime_type` | The file's MIME type |
| `size` | The file's size in bytes |
| `metadata` | The document's metadata |
| `status` | `created`, `processing`, `processed`, `indexing`, `ready`, or `error` |

| Method and path | Description |
|---|---|
| `GET /channel/documents` | Lists documents. See [List documents](#list-documents). |
| `POST /channel/documents` | Uploads a document. See [Upload a document](#upload-a-document). Returns `201`. |
| `GET /channel/documents/exists?filename=<name>&folder=<folder>` | Returns `{"exists": true}` when a document with this name is in this folder |
| `GET /channel/documents/{id}` | Returns a document |
| `PUT /channel/documents/{id}` | Replaces the file, in the multipart field `attachment`, or the metadata, in the field `metadata`, or both. A new file is processed and indexed again. |
| `DELETE /channel/documents/{id}` | Deletes the document, its file, chunks, and index records. Returns `204`. |
| `GET /channel/documents/{id}/download` | Returns the original file |
| `PUT /channel/documents/{id}/metadata` | Deprecated. Sets the metadata from a JSON body. Use `PUT /channel/documents/{id}`. |

### List documents

| Query parameter | Default | Description |
|---|---|---|
| `offset` | `0` | The number of documents to skip |
| `limit` | `25` | The most documents to return |
| `sort` | Newest ID first | `<field>` or `<field>,asc` or `<field>,desc`, and repeatable. Fields: `id`, `display_name`, `mime_type`, `size`, `status`, and sortable metadata fields. |
| `<field>[eq]` | — | Keeps documents whose string or string array field has this value. Repeat it for several values. |
| `<field>[start]`, `<field>[end]` | — | Keeps documents whose date field is in this range |

The response holds `total_count`, `offset`, `limit`, and `results`. Filters work only on [filterable fields](1.channel-configuration.md#metadata-schema).

```bash
curl -g "https://<DIAL_HOST>/v1/deployments/<APPLICATION_ID>/route/channel/documents?limit=10&sort=published_on,desc&category[eq]=annual-report" \
  -H "Api-Key: <DIAL_API_KEY>"
```

### Upload a document

The request is `multipart/form-data`:

| Part or parameter | Description |
|---|---|
| `attachment` | The file. Its MIME type must be one that the channel's [parsers](1.channel-configuration.md#parsers) accept. |
| `metadata` | Optional. A JSON object that matches the channel's metadata schema |
| `folder` query parameter | Optional. The folder to store the file in |
| `overwrite` query parameter | `true` replaces a document with the same name in the same folder. Otherwise such an upload fails. |

The backend stores the file in the application's bucket and starts indexing. With [background jobs](4.configuration/0.index.md#background-jobs), the response comes at once, with the status `created`. Otherwise it comes when indexing ends. An indexing failure then fails the request and sets the document's status to `error`. File names are compared without case.

## Indexing

| Method and path | Description |
|---|---|
| `PUT /channel/documents/{id}/reindex` | Indexes the document again. See [Reindex documents](#reindex-documents). |
| `GET /channel/stats` | Chunk statistics of every document |
| `GET /channel/documents/{id}/stats` | Chunk statistics of one document, page by page |

### Reindex documents

| Query parameter | Default | Description |
|---|---|---|
| `index` | All indexes | An index to rebuild. Repeat it for several. |
| `force` | `false` | `true` processes the document again and rebuilds all indexes, ignoring `index` |

A document whose status isn't `processed` or `ready` is processed first, whatever `force` is. The response is the document, with `202` when the work runs as a background job and `200` when it's done.

### Chunk statistics

Statistics count each document's text chunks, image chunks, and characters of text. `documents_without_text` counts documents with no text chunk. A `ready` document counted there was parsed without any text, for example a scanned PDF.

## Search and retrieval

| Method and path | Description |
|---|---|
| `POST /channel/documents/search` | Finds documents. See [Search documents](#search-documents). |
| `GET /channel/documents/search/schema` | The JSON schema of the search body for this channel |
| `POST /channel/retrieval` | Finds chunks. See [Retrieve chunks](#retrieve-chunks). |
| `GET /channel/retrieval/schema` | The JSON schema of the retrieval body |
| `GET /channel/metadata` | The metadata schema, as `schema`, and the values in use in filterable string and string array fields, as `dimensions` |
| `GET /channel/config` | The channel configuration, with its `channel_key` |

### Search documents

Document search uses the `document` [indexes](1.channel-configuration.md#indexes) and returns documents, most relevant first.

| Field | Default | Description |
|---|---|---|
| `query` | Required | The search query |
| `limit` | `5` | The most documents to return |
| `indexes` | The indexes with `include_in_hybrid` | The document indexes to search, by name |
| `matcher` | All documents | `filters` and `top_n`, as for the [`explicit` selector](1.channel-configuration.md#document-selectors) |

### Retrieve chunks

Retrieval runs the channel's retriever without an answer. The body has `query` and an optional `retriever` object, which is merged into the channel's retriever. It accepts the [per-request options](1.channel-configuration.md#per-request-options), such as `top_k` and a document selector.

```json
{
  "query": "risk outlook",
  "retriever": {
    "document_selector": {"type": "exact_documents", "document_ids": [3, 7]}
  }
}
```

The response is a list, most relevant first. Each item has `source_url`, `source_display_name`, and `source_metadata`, and a `result_type`:

- **`chunk`.** One chunk, with its fields: `chunk_type` (`text` or `image`), `document_id`, `chunk_id`, and `metadata`. A text chunk has `text`. An image chunk has `image_type`, `mime_type`, and `content` in base64.
- **`combined`.** Several chunks in `chunks`. The `classic` retriever returns a text chunk with its page image this way.

## Export and import

| Method and path | Description |
|---|---|
| `GET /channel/documents/{id}/export` | Downloads the document as a bundle: the file, metadata, status, chunks, and index records, in MessagePack |
| `POST /channel/documents/import` | Imports a bundle from the multipart field `attachment`. `overwrite=true` replaces a document of the same name. Returns `201`. |
| `PUT /channel/export` | Starts building the channel archive. Returns `202` and the status. |
| `GET /channel/export/status` | Returns the archive's status: `pending`, `ready`, `error`, or `not_found` |
| `GET /channel/export` | Downloads the archive. Returns `404` until it's ready. |
| `POST /channel/import` | Imports an archive from the multipart field `attachment`, of type `application/zip`. Returns `202`. |

The archive is a ZIP file with `_channel.json`, the channel configuration, and one bundle per document. The backend keeps it in the application's bucket, at `export/<channel key>.zip`, and deletes it at any change to the documents.

An archive imports only into a channel whose `metadata_schema`, `parsers`, and `indexes` are the same. Imported documents keep their chunks, index records, and status, so they aren't indexed again.

Building and importing an archive need [background jobs](4.configuration/0.index.md#background-jobs). Without them, `PUT /channel/export` fails with "Could not create channel archive.", and `POST /channel/import` fails with `500`.

## Job endpoints

`/channel/jobs/...` serves the backend's own job worker, which calls it through DIAL Core with `DIAL_API_KEY`. The endpoints stream their progress as server-sent events. Clients don't call them.
