# Roles

A **role** groups callers so DIAL Core can apply the same rules to all of them: which resources they may use, how many tokens and requests they may spend, how much money they may spend, and how they may share resources. A role name is a claim value from your identity provider, or a role assigned to an API key. This reference is for platform engineers who set access and usage limits; it assumes you know [how DIAL Core is configured](0.index.md).

Access to a model, application, toolset, or route is granted with its `userRoles` field. A role entry adds limits and sharing rules on top. For the concepts, see [Roles and rate limits](../../../4.operating-dial/5.auth-and-access-control/3.roles-and-rate-limits.md).

## Where roles are defined

| Source | Location |
|---|---|
| Config file | `roles.<name>` |
| Configuration API | `/v1/roles/platform/<name>` |

DIAL Admin manages roles in [Roles](../../../5.administering-dial-new/6.governance/1.roles.md).

## Fields

| Field | Description |
|---|---|
| `limits` | Token and request limits per deployment. See [Limits](#limits). |
| `costLimit` | Spending limits in USD across all models. See [Cost limits](#cost-limits). |
| `share` | Sharing limits per resource type. See [Sharing limits](#sharing-limits). |

When a role defines no limits for a deployment, the limits of the `default` role apply. When the `default` role defines none either, usage is unlimited.

## Limits

`limits` is a map keyed by deployment name.

| Field | Window | Description |
|---|---|---|
| `minute` | Floating | Tokens per minute. |
| `day` | Fixed calendar | Tokens per day. |
| `week` | Fixed calendar | Tokens per week. |
| `month` | Fixed calendar | Tokens per month. |
| `requestHour` | Floating | Requests per hour. |
| `requestDay` | Fixed calendar | Requests per day. |

- **Floating windows** (`minute`, `requestHour`) age usage out gradually as time passes, which spreads requests evenly.
- **Fixed calendar windows** (`day`, `week`, `month`, `requestDay`) reset all at once at a boundary aligned to the calendar; "this month" runs from the first to the last day of the calendar month. Usage cannot exceed the limit until the next boundary, whenever in the period it accrued. The deployment-wide [`rateLimitSchedule`](14.global-settings.md#rate-limit-schedule) sets the time zone, the first day of the week, and the reset time; without it, windows reset at 00:00 UTC, and weeks start on Monday.

`GET /v1/deployments/{deployment_id}/limits`, `GET /v1/user/limits`, and `GET /v1/user/usage` report the next boundary as `resetsAt` on each fixed-window entry. Floating-window entries have no `resetsAt`.

A request served through a [translator](6.translators.md#limits-and-usage) is counted once, on the translator's callback.

## Cost limits

`costLimit` caps spending across all models, in USD, with `minute`, `day`, `week`, and `month` fields. Cost limits work alongside token and request limits, and use model [pricing](4.models.md#pricing). The same `default` role fallback applies.

Callers who sign in through an identity provider can be governed by budgets instead, when `spendingLimits.mode` is `enforce`; callers with API keys always use `costLimit`. See [Spending limits](14.global-settings.md#spending-limits).

## Sharing limits

`share` is a map keyed by resource type, such as `APPLICATION` or `FILE`.

| Field | Default | Description |
|---|---|---|
| `invitation_ttl` | `invitations.ttlInSeconds` (72 hours) | The lifetime of a sharing invitation link, in hours. |
| `max_accepted_users` | `10` for `APPLICATION`, unlimited for other types | The maximum number of users who can accept an invitation to a shared resource. |

## Example

```json
{
  "roles": {
    "default": {
      "limits": {
        "gpt-4o": { "minute": "100000", "day": "2000000" }
      }
    },
    "analyst": {
      "limits": {
        "gpt-4o": {
          "requestHour": "20",
          "requestDay": "300",
          "minute": "200000",
          "day": "10000000",
          "week": "10000000",
          "month": "10000000"
        }
      },
      "costLimit": { "day": 100.0, "month": 2000.0 },
      "share": {
        "APPLICATION": { "invitation_ttl": "24", "max_accepted_users": "10" },
        "FILE": { "invitation_ttl": "24", "max_accepted_users": "10" }
      }
    }
  }
}
```
