# DIAL Core 0.49.0

DIAL Core 0.49.0 adds OpenTelemetry GenAI enrichment, Bearer upstream keys for routes, decision-tree pricing for prompt and completion rates, and usage per deployment. This page summarizes the release and its patch releases, 0.49.1 to 0.49.4, with a link to the full notes of each. It is for platform engineers who plan a DIAL Core upgrade.

Platform releases, which pin DIAL Core together with the other services, are in the [Changelog](../../../8.reference/changelog/index.md).

## 0.49.0

Released 2026-10-14. [Release notes](https://github.com/epam/ai-dial-core/releases/tag/0.49.0)

**Added**

- OpenTelemetry GenAI span enrichment and trace correlation response headers. See [Analytics and tracing](../1.configuration/2.settings/11.analytics-and-tracing.md#tracing).
- Spans for blob storage, resource, rate-limit, deployment resolution, authentication, and credentials calls.
- `authType: BEARER` on route upstreams, which sends the key as `Authorization: Bearer`. See [Routes](../1.configuration/10.routes.md#upstreams).
- Decision-tree pricing for `prompt` and `completion` rates. See [Models](../1.configuration/4.models.md#pricing).
- `rateLimitSchedule` in the global settings of the Configuration API. See [Global settings](../1.configuration/14.global-settings.md#rate-limit-schedule).
- `proxy.additionalHopByHopHeaders`, to strip extra headers from forwarded requests and responses. See [Server and client](../1.configuration/2.settings/1.server-and-client.md#proxying).
- `POST /openai/v1/chat/completions`, and `POST /openai/responses`, which mirrors `/openai/v1/responses`.
- A usage endpoint per deployment with real cost, Application spend in the usage and limits APIs, and an API that lists deployment names.
- Upstream-aware routing for encrypted content in the Responses API, with the deployment name in the affinity metadata.

**Fixed**

- `client.proxyOptions.host` is now used when Core fetches JWKS.
- `invitations.ttlInSeconds` is now the default invitation lifetime.
- Entity names can contain `(` and `)`, and the name pattern is enforced on admin validate and apply.
- The deployment listing no longer fails as a whole when one deployment is broken.
- Migrating models and routes keeps their encrypted secrets, and migrating a toolset clears stray PKCE artifacts.
- A key write whose secret another key already uses is rejected, and Core no longer returns a misleading `Unknown API key` error.
- Catalog properties are validated against their catalog schema.
- Core answers `502` when it cannot parse an interceptor's headers.
- Login statuses are returned on `GET` for platform toolsets and applications.
- A chained agent can reach its own declared prompts and skills.
- Configuration validation warnings name the model or deployment.
- Log lines keep their trace correlation after the client disconnects, and the Messages API response log includes a timing breakdown.
- Dependency upgrades for reported vulnerabilities, including `jackson-databind` 2.21.6 for CVE-2026-68497.
- Upgrades Guava to 33.7.2-jre.

**Changed**

- The `temperature` feature flag is turned off by default.
