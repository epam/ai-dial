# DIAL Core 0.48.0

DIAL Core 0.48.0 adds translators, per-interface routing settings for deployments and upstreams, fixed calendar windows for rate limits, and the configuration file migration endpoint. This page summarizes the release and its patch releases, 0.48.1 to 0.48.8, with a link to the full notes of each. It is for platform engineers who plan a DIAL Core upgrade.

Platform release 1.48 ships DIAL Core 0.48.0; see [Upgrade to DIAL 1.48](../../../8.reference/changelog/upgrade-to-1.48.md).

## 0.48.0

Released 2026-09-22. [Release notes](https://github.com/epam/ai-dial-core/releases/tag/0.48.0)

**Added**

- Translators for deployment interfaces, also in the admin Configuration API. See [Translators](../1.configuration/6.translators.md).
- `baseUrl` and `mode` in deployment interfaces, and `defaultHeaders`, `defaults`, `features`, and `overridePaths` per interface. See [Models](../1.configuration/4.models.md#interfaces).
- `interfaces` and `baseUrl` on upstreams. See [Load balancing and upstreams](../1.configuration/5.load-balancing.md#upstream-interfaces).
- `defaultHeaders` on deployments.
- Fixed calendar windows for `day`, `week`, and `month` rate limits. See [Roles](../1.configuration/12.roles.md#limits).
- The configuration file migration endpoint. See [Configuration API](../1.configuration/1.configuration-api.md#move-file-configuration-to-the-platform-bucket).
- Client secrets are masked in API responses.
- `GET /v1/deployments/{deployment_id}`, per-interface configuration in deployment listings, and Anthropic models listing.
- `userDisplayName` in the user info response. See [Identity providers](../1.configuration/2.settings/4.identity-providers.md).
- Custom skills in the Unified API chat completion request, the `skillsSupported` feature flag, and auto-sharing of skill resources declared in the configuration.
- Decision-tree pricing for cache reads and writes, for provider rates that depend on TTL and service tier. See [Models](../1.configuration/4.models.md#pricing).
- Short-name resolution of entities, with a schema index by `$id`.
- API key sign-in is skipped when the submitted key is unchanged.
- Upstream-aware routing for encrypted content in the Responses API.

**Fixed**

- A key no longer stops working after a `PUT` that omits the `key` field.
- Applications can use `interfaces` as their only routing target.
- Translator references are resolved at request time instead of being copied into deployments.
- Background Responses jobs follow the `interfaces` configuration, and send the per-request key when they poll.
- A chat completion no longer answers `403` when an application references a DIAL skill resource.
- Roles without any limits are handled.
- Migration results report `kind`, `resourceUrl`, and `key` instead of an ambiguous ID.
- Skill metadata returns the right node types and descriptions, and shared skill item metadata no longer answers `403`.
- GCP KMS encryption no longer fails with `NoSuchFieldError`.
- An empty `apiKeyHeader` in toolset authentication settings is rejected.
- Permission checks in the application listing are batched, and parsed application type schemas are cached.
- Netty is upgraded to 4.2.17.Final for CVE-2026-75595.
