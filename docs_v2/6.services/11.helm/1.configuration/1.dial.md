# DIAL platform chart configuration

The `dial/dial` chart installs a selected set of DIAL services in one Helm release. This reference describes chart **8.1.0**, its dependency aliases, and the settings inherited from the child charts. It is for platform engineers preparing an assembly values file.

## Dependencies and images

The [8.1.0 Chart.yaml](https://github.com/epam/ai-dial-helm/blob/dial-8.1.0/charts/dial/Chart.yaml) pins Core chart `6.0.0` and Extension chart `3.1.1`. The [assembly values](https://github.com/epam/ai-dial-helm/blob/dial-8.1.0/charts/dial/values.yaml) override their images:

| Alias | Enabled by default | Image tag | Child chart |
|---|---|---|---|
| `core` | `true` | `epam/ai-dial-core:0.49.2` | `dial-core` |
| `chat` | `true` | `epam/ai-dial-chat:1.2.4` | `dial-extension` |
| `themes` | `true` | `epam/ai-dial-chat-themes:0.21.0` | `dial-extension` |
| `openai` | `false` | `epam/ai-dial-adapter-openai:0.45.0` | `dial-extension` |
| `bedrock` | `false` | `epam/ai-dial-adapter-bedrock:0.45.0` | `dial-extension` |
| `vertexai` | `false` | `epam/ai-dial-adapter-vertexai:0.41.1` | `dial-extension` |
| `dial` | `false` | `epam/ai-dial-adapter-dial:0.20.0` | `dial-extension` |

The last alias is the DIAL-to-DIAL adapter, not the parent chart itself. `extraDeploy` accepts additional manifests at the assembly level. Bitnami `common` is a template-library dependency.

## Values below an alias

| Value family | Purpose |
|---|---|
| `<alias>.enabled` | Include or omit that dependency. |
| `<alias>.image` | Override registry/repository/tag/digest and pull settings. |
| `<alias>.env`, `.secrets`, `.extraEnvVars`, `.extraEnvVarsSecret`, `.extraEnvVarsCM` | Supply service-specific configuration. |
| `<alias>.service`, `.containerPorts`, `.ingress`, `.httpRoute` | Configure internal service ports and external routing. |
| `<alias>.resources`, `.replicaCount`, `.autoscaling.hpa`, `.pdb` | Resource allocation, scaling, and disruption controls. |
| `<alias>.livenessProbe`, `.readinessProbe`, `.startupProbe` | Workload health checks. The assembly enables liveness/readiness on its services. |
| `core.configuration`, `core.valkey`, `core.persistence`, `core.logger` | Core-specific encryption, cache, file storage, and log shipping. See [Core chart](2.dial-core.md). |

An enabled adapter must also receive its provider credentials and have model entries registered in Core. Enabling its pod alone does not create a usable model. See [OpenAI](../../4.openai-adapter/0.index.md), [Bedrock](../../5.bedrock-adapter/0.index.md), and [Vertex AI](../../6.vertex-ai-adapter/0.index.md) for runtime settings.

```yaml
core:
  valkey:
    enabled: false
  env:
    aidial.redis.singleServerConfig.address: redis://<CACHE_HOST>:6379
  extraEnvVarsSecret: core-runtime-secrets

chat:
  env:
    DIAL_CORE_URL: http://dial-core.dial.svc.cluster.local
  extraEnvVarsSecret: chat-auth-secrets

openai:
  enabled: true
  env:
    DIAL_URL: http://dial-core.dial.svc.cluster.local
```

This fragment illustrates alias scope in a Helm release named `dial` in namespace `dial`; it assumes existing configuration and authentication Secrets. The generated Service name can change with naming overrides. Complete installation examples are linked below.

## Provider examples

The release includes [example values](https://github.com/epam/ai-dial-helm/tree/dial-8.1.0/charts/dial/examples) for AWS, Azure, GCP, and generic Kubernetes. Cloud examples distinguish simple and complete deployments. The generic complete directory is a placeholder; use its simple example and the [generic Kubernetes guide](../../../4.operating-dial/2.cloud-deployment/4.generic-kubernetes.md).

Simple examples are starting points for evaluation; configure sign-in, encryption, durable storage, cache access, and provider credentials for the target environment. The guide for each cloud remains under [Operating DIAL](../../../4.operating-dial/2.cloud-deployment/0.index.md).
