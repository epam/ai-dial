# Evaluation Framework Backend 0.5.0

Evaluation Framework Backend 0.5.0 adds Application mode for long runs and an inbound MCP server, renames the API-key role-mapping variables, and changes how test case scores are calculated. This page summarizes the deployment changes for platform engineers who plan an upgrade. There are no patch releases.

## 0.5.0

Released 2026-10-14. [Full release notes](https://github.com/epam/ai-dial-admin-evaluation-framework-backend/releases/tag/0.5.0)

**Breaking**

- `API_KEY_ROLES_MAPPING` is renamed `API_KEY_KEY_ROLES_MAPPING`, and `API_KEY_DEFAULT_ROLES_MAPPING` is renamed `API_KEY_JWT_ROLES_MAPPING`. The old names aren't read. Setting both old names stops startup; renaming only one leaves the other mapping empty. This affects every deployment with `API_KEY_ENABLED=true`.

**Added**

- Optional [Application mode](../1.configuration/1.framework-backend.md#application-mode): runs go through a DIAL Core application route with a per-request key, so a run no longer fails when the user's token expires. It needs `API_KEY_ENABLED=true`, `DIAL_APP_PROXY_ENABLED=true`, and an application registered in Core.
- An [inbound MCP server](../1.configuration/1.framework-backend.md#inbound-mcp-server), off by default, with the `list_deployments` and `get_deployment` tools.
- Limits for ZIP imports of test cases: `CSV_IMPORT_ZIP_MAX_ENTRIES`, `CSV_IMPORT_ZIP_MAX_TOTAL_UNCOMPRESSED_SIZE`, and `CSV_IMPORT_ZIP_MAX_MANIFEST_SIZE`. ZIP exports gain a `manifest.json`, and imports are transactional.
- Total run costs in run queries, with `QUERY_DSL_EXTENSION_TEST_SUITE_RUN_COST_ENABLED`.

**Changed**

- A test case's score is calculated across all its turns, requests, and reruns, and skipped metrics are left out. Average run costs are calculated per test case instead of per request.
- Run costs call `POST /v1/queries/execute-sql` on the Analytics data-access service. Check that your version of that service has the endpoint.
- Dataset schema fields have stable IDs, so renaming a field keeps its values. Destructive schema changes and imports on a public dataset that a test suite uses answer `409`.
- With identity providers configured, API-key roles are read from the claims of the provider that issued the token. `API_KEY_USER_CLAIMS_ROLE_CLAIM` becomes the fallback.

**Fixed**

- Application and model targets list again after DIAL Core changed the format of model pricing.
- Jackson is upgraded for several CVEs.

**Database migrations**

Flyway applies them at startup. The database user needs DDL privileges on both schemas, and the analytics database must be reachable while meta `V1_33` copies the run metric snapshots.

| Database | Migrations | Change |
|---|---|---|
| meta | `V1.32` to `V1.34` | Run metric snapshots move to the meta database, with cascading deletion |
| meta | `V1.35`, `V1.36` | Score aggregation on test suites; stable IDs for dataset schema fields |
| analytics | `V1.20`, `V1.21` | Per-test-case metric aggregates; one test case score row per case and computation |

**Warning**
> Analytics `V1.21` drops and recreates `test_case_eval_scores`, so existing derived scores are gone until they are recalculated. Meta `V1.34` locks its table while it replaces an index. Plan a maintenance window for large installations.

**API changes**

These matter to clients of the backend's REST API, such as scripts and `eval-cli`. Template variables are returned per request of a chain. Eval summary responses no longer carry `score` and `passed`. New endpoints include `POST /mcp`, `POST /api/v1/costs/test-suite-runs`, and `GET /api/v1/test-suites/{testSuiteId}/metric-definitions/aggregated`. See the full release notes for the complete list.
