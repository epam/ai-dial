# Quick Apps Frontend 0.3.0

Quick Apps Frontend 0.3.0 replaces the editor's Next.js server with a static app served by the DIAL Chat BFF. This changes the image, every environment variable, and the sign-in redirect URI. The release also reworks the editor, with skills, application credentials, separate Toolsets and Agents rows, and a Knowledge base add-on. This page summarizes the release and its patch release, 0.3.1, with a link to the full notes of each. It is for platform engineers who plan a Quick Apps upgrade.

| Version | Date | Type |
|---|---|---|

## 0.3.0

Released 2026-10-14. [Release notes](https://github.com/epam/ai-dial-quickapps-frontend/releases/tag/0.3.0)

**Breaking**

- The image is now the DIAL Chat BFF, `chat-api`, with the editor's static build. It is amd64-only, listens on port `5000`, and has its health check at `/<API_PREFIX>/health`.
- The sign-in redirect URI moves from `/api/auth/callback/<provider>` to `/api/v1/auth/callback/<provider>`. Update it in every identity provider.
- The application name comes from the `applicationName` query parameter of the editor URL. Upgrade DIAL Chat first: without `applicationName`, **Save** and **Preview** stay disabled. The DIAL Admin host doesn't send it yet.

**Added**

- Chat skills instead of prompts in the editor.
- Application credentials: the agent details popup opens the host's credential forms, when the host advertises `applicationCredentials=true`.
- Separate Toolsets and Agents rows.
- A redesigned Skills add-on that previews skill files by type, and conversation starters moved into Add-ons.
- A Knowledge base add-on with a file picker; a selected folder is added as a folder.
- Catalog-style details for skills, Toolsets, and agents, and a Settings tab for agents, with **Connect via** MCP or Chat Completion.
- A search field and tool count on a Toolset's Tools tab.
- A Settings row with an **Advanced Settings** popup: temperature, file processing, attachments, and feature toggles.
- New apps get an orchestrator temperature of `0.5`, and Instructions can't be blank.
- A redesigned editor layout, model picker, and sign-in screens.
- Several origins in `allowedOrigin`, and the `VALIDITY_STATE` message, with `SAVE_ERROR` for a save blocked by validation.

**Fixed**

- Shared apps are no longer read-only; read-only now comes only from the host.
- Toolset and agent IDs are saved encoded once.
- The display version from `TRIGGER_SAVE` is saved.
- An MCP-only application added as an agent shows its name, not `unknown`.
- The editor fits mobile screens.

**Security**

- `zlib` patched in the image, for CVE-2026-85091.

**Changed on upgrade**

The old variable names are no longer read:

| Old variable | New variable or location |
|---|---|
| `NEXTAUTH_SECRET` | `AUTH_SESSION_SECRET` |
| `NEXTAUTH_URL` | `AUTH_CALLBACK_BASE_URL`; set `CORS_ORIGIN` separately |
| `THEMES_URL` | `THEMES_CONFIG_URL`, now the base URL; `/config.json` is added |
| `ALLOWED_FRAME_ANCESTORS` | `ALLOWED_IFRAME_ORIGINS` |
| `QUICK_APPS_DEFAULT_MODEL` | `DEFAULT_DEPLOYMENT` |
| `AUTH_<PROVIDER>_ISSUER`, `AUTH_<PROVIDER>_CLIENT_SECRET` | `AUTH_<PROVIDER>_HOST`, `AUTH_<PROVIDER>_SECRET`, per provider |
| `CODE_INTERPRETER_ENABLED`, `WEB_FETCH_ENABLED`, `ADD_ATTACHMENT_ENABLED` | `CUSTOM_CLIENT_VARIABLES` keys `codeInterpreterEnabled`, `webFetchEnabled`, `addAttachmentEnabled`, as boolean `true` |
| `ALLOWED_ORIGIN`, `DIAL_ADMIN_URL`, `DIAL_CHAT_URL` | `CUSTOM_CLIENT_VARIABLES` keys `allowedOrigin`, `dialAdminHost`, `dialChatHost` |
| `QUICK_APPS_APPLICATION_NAME` | The `applicationName` query parameter, with no fallback |

New variables: `CORS_ORIGIN`, `AUTH_SESSION_SECRET`, `AUTH_CALLBACK_BASE_URL`, `AUTH_POST_LOGOUT_REDIRECT_URI`, `AUTH_SESSION_COOKIE_NAME`, `AUTH_TRANSACTION_COOKIE_NAME`, `AUTH_LEGACY_COOKIE_NAMES`, `CSP_MODE`, `ALLOWED_CONNECT_ORIGINS`, `OVERLAY_ENABLED`, `API_PREFIX`, and `OTEL_SDK_DISABLED`. See [Frontend configuration](../3.configuration/2.frontend.md). Set `AUTH_LEGACY_COOKIE_NAMES` to the old `next-auth` cookie names to avoid `HTTP 431` after the upgrade.
