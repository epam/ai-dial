# Quick Apps Backend 0.13.0

Quick Apps Backend 0.13.0 adds Hooks 2.0, tools hidden from the model, a per-user tool access filter, and nested stages for called Quick Apps. It also rejects client system messages by default. This page summarizes the release and its patch releases, 0.13.1 and 0.13.2, with a link to the full notes of each. It is for platform engineers who plan a Quick Apps upgrade.

## 0.13.0

Released 2026-10-14. [Release notes](https://github.com/epam/ai-dial-quickapps-backend/releases/tag/0.13.0)

**Added**

- [Preview] Hooks 2.0: an `on_completion` event after a finished turn, a `timeout_seconds` per hook, and `arguments` rendered as [JSON-e](https://json-e.js.org) templates against the conversation.
- [Preview] `hidden_from_model` on `mcp`, `dial-mcp`, and `dial-app` Toolsets: the tools stay callable by hooks, but the model isn't offered them.
- [Preview] Dynamic tool discovery covers `dial-deployment` Toolsets too.
- [Preview] Several skills from one chat message, up to `SKILL_INVOCATION_MAX_SKILLS_PER_MESSAGE`.
- Per-user tool access filter, `features.tool_access_filter.enabled`. DIAL tools the user can't access are hidden from the model, instead of failing with `403`. It needs DIAL Core 0.49.0; on an older Core it offers every tool.
- The stages of a called Quick App appear under its `Calling X` stage, at any depth.
- `orchestrator.attachment_strategy.accepted_types` narrows the MIME types the orchestrator may load.
- `custom_fields.configuration` in the orchestrator's `deployment.parameters` is forwarded, for model features such as Anthropic `betas`.

**Fixed**

- A client system message no longer replaces the whole system prompt, dropping skills and MCP resources. It is rejected with `400`.
- An unknown tool name goes back to the model as a tool error, instead of a `500`.
- Oversized tool error messages are cut before they reach the orchestrator.
- Synthetic tool-call stages show real durations, and MCP and REST API stage titles name the tool.
- [Preview] `internal_representation_add_attachment` infers the attachment type, and the **Add attachment** stage shows the file.

**Security**

- `urllib3` 2.8.0, for CVE-2026-97687, CVE-2026-97688, and CVE-2026-97689.

**Changed**

- `pyjwt` upgraded to 2.15.1.

**Changed on upgrade**

- A request with a non-empty `system` message fails with `400`. Set `ALLOW_OVERRIDE_SYSTEM_MESSAGE=true` for clients that send one. Otherwise, add `"systemPromptSupported": false` to each Quick App's `features`. See [Quick App applications](../3.configuration/3.dial-core-and-chat.md#quick-app-applications).
- Nested sub-app stages are on. Turn them off with `features.stage_display.propagate_sub_stages: false`.
- [Preview] A literal `${` in hook `arguments` is now interpolated; escape it as `$${`. `on_request_start` hooks time out after 15 seconds unless `timeout_seconds` is set.
- New variables: `ALLOW_OVERRIDE_SYSTEM_MESSAGE` and `SKILL_INVOCATION_MAX_SKILLS_PER_MESSAGE`. See [Backend configuration](../3.configuration/1.backend.md).

## Patch releases

### 0.13.1

Released 2026-10-16. [Release notes](https://github.com/epam/ai-dial-quickapps-backend/releases/tag/0.13.1)

- **Changed on upgrade:** the predefined `dial_rag` tool no longer re-sends the files of its earlier calls, which widened each search to every document in the conversation. It applies to apps that use the `dial_rag` template, directly or through the `chathub` Toolset. Apps with their own inline `dial-rag` tool keep their own setting.

### 0.13.2

Released 2026-10-27. [Release notes](https://github.com/epam/ai-dial-quickapps-backend/releases/tag/0.13.2)

- **Changed on upgrade:** ten Preview features become Stable and work whatever `ENABLE_PREVIEW_FEATURES` says. They are tool discovery, deferred Toolsets, web fetch, representation tooling, hooks, citation annotation propagation, tools hidden from the model, DIAL skill resources, skill invocation from a message, and folder contexts. Tool-call result offload stays in Preview.
- **Changed on upgrade:** with preview off, settings of those features that were ignored in existing manifests now take effect. An app with `features.web_fetch.enabled: true` shows a failed **Initialization issues** stage on every turn until `EXTERNAL_URL_FETCH_ENABLED` is on. The `MIN_TOOLS_FOR_DEFERRAL`, `DIAL_SKILLS_*`, and `SKILL_INVOCATION_MAX_SKILLS*` limits apply too.
- **Security:** `certifi` 2026.10.19, for GHSA-6q48-6c7w-9gw2; OpenTelemetry 1.45.1 and 0.66b1, for CVE-2026-114603; and `fastmcp` 3.4.11, for GHSA-7xgj-8392-5q4r.
