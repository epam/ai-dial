# Quick Apps Backend 0.12.0

Quick Apps Backend 0.12.0 adds dynamic tool discovery, DIAL skill resources, skill invocation from a message, and citation propagation, all in Preview. It also reworks the tool fallback strategies. This page summarizes the release and its patch release, 0.12.1, with a link to the full notes of each. It is for platform engineers who plan a Quick Apps upgrade.

| Version | Date | Type |

| [0.12.1](#0121) | 2026-10-13 | Patch |

## 0.12.0

Released 2026-09-22. [Release notes](https://github.com/epam/ai-dial-quickapps-backend/releases/tag/0.12.0)

DIAL Core 0.48.0 or later is required for skills: the `dial-skill` type and skill invocation from a message.

**Added**

- [Preview] Dynamic tool discovery, `orchestrator.tool_discovery.enabled`. Deferred REST API, MCP, and internal Toolsets are left out of the first LLM request and found on demand through `internal_tool_search`. Toolsets smaller than `min_tools_for_deferral` are loaded at once.
- [Preview] The `dial-skill` skill type, for skills stored as DIAL skill resources. The agent reads `SKILL.md` and opens bundled files with `read_skill`.
- [Preview] Skill invocation from a chat message: a skill picked on the message, `custom_content.skills`, is loaded before the model answers.
- [Preview] Citation annotations from a deployment tool carried into the answer, with `propagate_annotations_to_choice`.
- `deployment.parameters` accepts `reasoning_effort` and `static_function` tools, such as web-search grounding.
- Reworked tool fallbacks: the tool error always reaches the LLM, and the new `hard_stop` strategy ends the agent loop.

**Fixed**

- `propagate_types_to_choice` applies to attachments the orchestrator echoes back.
- `internal_attachments_get_content` no longer adds the files it reads to the answer.
- Tool names that start with a digit are prefixed with `_`; Gemini orchestrators rejected them.

**Security**

- `libuuid` 2.42.3-r1, for CVE-2026-53612 and six other CVEs.

**Changed**

- Requests with fields the SDK doesn't model yet, such as `custom_content.skills`, are accepted instead of failing validation.

**Changed on upgrade**

- A failed tool call returns `The tool call failed with an error: <text>` to the model, both by default and for every `continue` and `retry` strategy.
- A `reasoning_effort` under `deployment.parameters` now reaches the deployment. For the orchestrator, it is dropped with a warning when the deployment doesn't advertise `features.reasoningEfforts`.
- Deprecated in manifests: the `retry` strategy, now `continue`; the `stop` strategy, now `hard_stop`; and `forward_tool_error_message`, now a no-op.
- New variables: `MIN_TOOLS_FOR_DEFERRAL`, `DIAL_SKILLS_FILE_MAX_BYTES`, `DIAL_SKILLS_MAX_FILES`, `DIAL_SKILLS_LISTING_MAX_PAGES`, and `SKILL_INVOCATION_MAX_SKILLS`. See [Backend configuration](../3.configuration/1.backend.md#skills).

## Patch releases

### 0.12.1

Released 2026-10-13. [Release notes](https://github.com/epam/ai-dial-quickapps-backend/releases/tag/0.12.1)

- **Fixed:** a client system message is rejected with `400`, instead of replacing the whole system prompt. With the new `ALLOW_OVERRIDE_SYSTEM_MESSAGE=true`, it replaces only the configured prompt. Add `"systemPromptSupported": false` to each Quick App's `features`. See [Quick App applications](../3.configuration/3.dial-core-and-chat.md#quick-app-applications).
- **Security:** `urllib3` 2.8.0, for CVE-2026-97687, CVE-2026-97688, and CVE-2026-97689.
