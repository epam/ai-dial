# DIAL Code Interpreter configuration

This reference covers Code Interpreter **0.2.0**, Core **0.49.4**, and Quick Apps Backend **0.13.2**. It is for platform engineers enabling Python calculations for agents. It assumes the [interpreter dependencies](0.index.md#dependencies-and-deployment-modes) are available.

## Where each setting lives

| Place | What it controls | Reference |
|---|---|---|
| Interpreter container environment | Upload size, download buffer, file directory, logging, and session header check | [Service environment](#service-environment) |
| Core static settings | Controller endpoint, session image, deployment mode, expiry, and user permissions | [Core session settings](#core-session-settings) |
| App Controller settings | Kubernetes namespaces, container resources, session probes, and startup wait | [Controller configuration](../16.app-controller/1.configuration.md) |
| Quick Apps Backend environment | API base URL, credentials, and client retries | [Quick Apps connection](#quick-apps-connection) |
| Quick App manifest or editor | Whether the Python tool is offered to the orchestrator | [Enable calculations in a Quick App](#enable-calculations-in-a-quick-app) |

## Service environment

The first five variables are read by [env.py](https://github.com/epam/ai-dial-code-interpreter/blob/0.2.0/aidial_code_interpreter/env.py#L1-L7). Values must be valid at process startup.

| Variable | Default | Description |
|---|---|---|
| `UPLOAD_MAX_SIZE` | `536870912` | Maximum uploaded file size, in bytes: 512 MiB. An oversized upload returns HTTP `413` and removes the partially written file. |
| `DOWNLOAD_CHUNK_SIZE` | `8192` | Buffer size used when streaming a file download, in bytes: 8 KiB. |
| `MOUNT_FOLDER` | Process working directory; `/mnt/data` in the image | Base directory used by upload, download, and file listing operations. Resolved to an absolute path at startup. |
| `LOG_LEVEL` | `INFO` | Interpreter logger level, converted to uppercase. |
| `SESSION_ID` | — | When set, operation requests must supply the same value in `x-dial-session-id`. Core supplies the deployment ID in its pod-backed session mode. |
| `TIMEOUT_KEEP_ALIVE` | `60` | Uvicorn HTTP keep-alive timeout, in seconds. Read by the image's startup command, not by `env.py`. |

The image also sets `PYTHONDONTWRITEBYTECODE=1` and `PYDEVD_DISABLE_FILE_VALIDATION=1`; see [Dockerfile](https://github.com/epam/ai-dial-code-interpreter/blob/0.2.0/Dockerfile#L32-L42). The HTTP API listens on `0.0.0.0:8080` in the published image.

`SESSION_ID` is optional at the service level. When it is set, missing headers return HTTP `400` and mismatches return HTTP `503`. `/health` does not require the header. See [session checking](https://github.com/epam/ai-dial-code-interpreter/blob/0.2.0/aidial_code_interpreter/app.py#L120-L129).

## Kernel timing and state

The interpreter constructs its Python kernel with a **10-second startup timeout** and a **60-second execution timeout**. These are constructor defaults, not environment variables in this release. Code Interpreter **0.2.0** exposes no environment setting to increase them.

Successful calls reuse the kernel and its variables. Execution exceptions restart it, including a timeout while waiting for kernel messages. A normal Python error is returned as `status: FAILURE`; it does not take the exception/restart path merely because Python raised an error. See [Interpreter](https://github.com/epam/ai-dial-code-interpreter/blob/0.2.0/aidial_code_interpreter/interpreter.py#L21-L115).

HTTP keep-alive, kernel execution timeout, client timeout, and Core's idle session lifetime are independent settings.

## Core session settings

The `applications` and `codeInterpreter` objects are static Core settings; changes require a Core restart.

| Setting | Default | Description |
|---|---|---|
| `applications.controllerEndpoint` | — | App Controller URL. Interpreter operations require an active controller connection. |
| `applications.controllerTimeout` | `240000` | Controller operation timeout, in milliseconds. |
| `applications.controllerConnectTimeout` | `10000` | Controller connection timeout, in milliseconds. |
| `codeInterpreter.sessionImage` | — | Interpreter image used when starting a session. Without it, interpreter operations are unavailable. |
| `codeInterpreter.sessionProxyUrl` | — | Unset: sessions use Knative deployments. Set: sessions use pods and requests pass through this proxy URL. |
| `codeInterpreter.sessionTtl` | `600000` | Idle lifetime after the last session use, in milliseconds: 10 minutes. |
| `codeInterpreter.checkPeriod` | `10000` | Expiration scan interval, in milliseconds. |
| `codeInterpreter.checkSize` | `256` | Maximum expired-session candidates processed per scan. |

Sources: [ApplicationOperatorService](https://github.com/epam/ai-dial-core/blob/0.49.4/server/src/main/java/com/epam/aidial/core/server/service/ApplicationOperatorService.java#L39-L54) and [CodeInterpreterService](https://github.com/epam/ai-dial-core/blob/0.49.4/server/src/main/java/com/epam/aidial/core/server/service/codeinterpreter/CodeInterpreterService.java#L80-L121). The Quick Apps tool description mentions 15 minutes; the actual idle lifetime follows Core's configured `sessionTtl`.

Core checks interpreter execution permission through the same `access.createCodeAppRoles` control used for Code App creation. The check passes when the setting is unset or the request carries a per-request key. Quick Apps calls with the per-request key it receives from Core, so this setting does not restrict its calculation tool. Session resources and DIAL file transfers are scoped through the caller's context. See [Core access settings](../1.core/1.configuration/2.settings/7.access.md), [CodeInterpreterController](https://github.com/epam/ai-dial-core/blob/0.49.4/server/src/main/java/com/epam/aidial/core/server/controller/CodeInterpreterController.java#L375-L378), and [AccessService](https://github.com/epam/ai-dial-core/blob/0.49.4/server/src/main/java/com/epam/aidial/core/server/security/AccessService.java#L126-L133).

Example settings fragment for Knative-backed sessions:

```json
{
  "applications": {
    "controllerEndpoint": "http://dial-app-controller:8080"
  },
  "codeInterpreter": {
    "sessionImage": "epam/ai-dial-code-interpreter:0.2.0",
    "sessionTtl": 600000,
    "checkPeriod": 10000,
    "checkSize": 256
  }
}
```

The Knative infrastructure must exist for this example. Pod-backed mode additionally needs a compatible session proxy and its `sessionProxyUrl`; setting the URL alone does not deploy that proxy.

## Quick Apps connection

| Variable | Default | Description |
|---|---|---|
| `PY_INTERPRETER_URL` | `DIAL_URL` when unset or empty | Base URL of the Core-compatible interpreter session API. The client appends `/v1/ops/code_interpreter`. |
| `PY_INTERPRETER_LOCAL_RUN` | `false` | `false` uses the incoming DIAL request key. `true` requires and selects `PY_INTERPRETER_API_KEY`. It does not change the client API paths to the raw container endpoints. |
| `PY_INTERPRETER_API_KEY` | — | Explicit API key required when `PY_INTERPRETER_LOCAL_RUN=true`. |
| `PY_INTERPRETER_DEFAULT_SESSION_ID` | — | Fallback session ID when the conversation does not already provide one. |
| `PY_INTERPRETER_CLIENT_MAX_RETRIES` | `3` | Client retry setting. |

The normal setup needs no interpreter-specific URL override: the Quick Apps Backend uses `DIAL_URL` and the incoming request key. Sources: [client construction](https://github.com/epam/ai-dial-quickapps-backend/blob/0.13.2/src/quickapp/internal_tooling/internal_tooling_module.py#L125-L176) and [API paths](https://github.com/epam/ai-dial-quickapps-backend/blob/0.13.2/src/quickapp/internal_tooling/py_interpreter_tooling/_py_interpreter_client.py#L27-L49).

Client timeouts follow the Quick App's `tool_defaults.timeout_seconds`, or the backend's `DEFAULT_TOOL_TIMEOUT_SECONDS` default of `300.0`. The deprecated `PY_INTERPRETER_CLIENT_TIMEOUT` overrides that backend default only when explicitly set and no app-level timeout exists. Increasing a client timeout does not increase the kernel's 60-second execution timeout. See [Quick Apps Backend configuration](../8.quick-apps/3.configuration/1.backend.md#python-interpreter).

## Enable calculations in a Quick App

The editor's **Code Interpreter** toggle adds the Python interpreter tool. The equivalent `tool_sets` fragment in the application's manifest is:

```json
{
  "tool_sets": [
    {"type": "predefined", "template_name": "py_interpreter"}
  ]
}
```

This fragment is added to an existing Quick App configuration with a tool-capable orchestrator. It references the shipped [predefined Toolset](https://github.com/epam/ai-dial-quickapps-backend/blob/0.13.2/config/predefined/toolset/py_interpreter.json#L1-L11). The user-facing toggle is documented in [Build a Quick App](../../7.chat-user-guide/3.catalog/2.agents.md#build-a-quick-app).

After deployment, a prompt such as “Use Python to calculate the mean of 12, 18, and 24” exercises session creation and execution. A Python execution stage and an answer containing `18` provide a functional check. A file-analysis check additionally exercises the attachment transfer path.

## Troubleshooting

| Symptom | What to check |
|---|---|
| Core reports interpreter unavailable (`503`) | `sessionImage`, `controllerEndpoint`, controller reachability, and workload startup. |
| Execution is forbidden (`403`) | The caller's roles and Core's `access.createCodeAppRoles` setting. Requests with a per-request key skip the role check. |
| Quick Apps gets `404` for interpreter operations | `PY_INTERPRETER_URL` must serve Core-style `/v1/ops/code_interpreter/*` paths, not only raw `/execute_code`. A previously used session may also have expired. |
| Execution returns `FAILURE` after a timeout | The kernel execution timeout is 60 seconds; changing HTTP keep-alive or Core session TTL does not extend it. |
| Variables disappear between requests | A new session, Core idle expiry, explicit close, or a kernel restart after an execution exception. |
| Session header is missing or mismatched | Core's session deployment ID, proxy routing, and the container's `SESSION_ID`. |
| Upload fails with `413` | The interpreter's `UPLOAD_MAX_SIZE` and any limits on the preceding proxy path. |
