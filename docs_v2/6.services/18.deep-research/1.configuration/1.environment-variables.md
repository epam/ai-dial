# DIAL Deep Research environment variables

This reference lists backend **0.4.0** deployment settings for platform engineers familiar with the [configuration overview](0.index.md). Defaults come from the released settings model and environment reads. Per-application sources, prompts, and limits belong in [application properties](2.application-properties.md).

## Server and DIAL connection

| Variable | Default | Description |
|---|---|---|
| `DIAL_URL` | — | Required HTTP(S) URL of DIAL Core, used for model calls, application properties, files, and deployment-mode MCP. |
| `APP_HOST` | `0.0.0.0` | HTTP bind address. |
| `APP_PORT` | `5000` | HTTP bind port. Core's registered endpoint addresses must use the reachable port. |
| `DIAL_APP_NAME` | `deep-research` | Application name used for logging and SDK telemetry. Does not rename the fixed completion deployment. |
| `HEARTBEAT_INTERVAL` | `5` | SSE heartbeat interval in seconds; integer, at least `1`. |
| `LLM_CACHE_POLICY` | — | Optional `availability-priority` or `cache-priority`, sent as `X-DIAL-CACHE-POLICY` on model calls. Unset sends no policy header. |
| `MAX_CONTEXT_IMAGES` | `50` | Maximum image content blocks in an LLM request; integer, at least `1`. |

Sources: [server settings](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/settings.py#L29-L34), [DIAL and image settings](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/settings.py#L52-L67), and [cache-policy header](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/utils/llm.py#L112-L134).

`LLM_CACHE_POLICY` controls Core's retry routing; it does not enable prompt caching. Core's model deployment must support and enable the appropriate caching behavior. See [Prompt caching](../../../3.building-with-dial/9.advanced-topics/1.prompt-caching.md).

The backend has no static `DIAL_API_KEY` deployment setting. Its SDK propagates the current request's key to Core calls. `REMOTE_DIAL_URL`, `REMOTE_DIAL_API_KEY`, and the CLI's `DIAL_API_KEY` belong to upstream development scripts, not this runtime settings model.

## Model deployment mappings

Every model enum has an optional `LLM_MODELS_<ENUM_NAME>` override. The value is a DIAL Core deployment ID, not a provider credential or URL.

| Variable | Default | Description |
|---|---|---|
| `LLM_MODELS_GPT_5_6_TERRA` | `gpt-5.6-terra-2026-07-09` | Mapping used by the backend's default model configuration. |
| `LLM_MODELS_GPT_5_6_LUNA` | `gpt-5.6-luna-2026-07-09` | Mapping for this enum member when selected in code. |
| `LLM_MODELS_GPT_5_4_2026_03_05` | `gpt-5.4-2026-03-05` | Mapping for this enum member when selected in code. |
| `LLM_MODELS_GPT_5_4_2026_03_05_REASONING` | `gpt-5.4-2026-03-05-reasoning` | Mapping for this enum member when selected in code. |
| `LLM_MODELS_GPT_5_2_2025_12_11` | `gpt-5.2-2025-12-11` | Mapping for this enum member when selected in code. |
| `LLM_MODELS_CLAUDE_OPUS_4_6` | `anthropic.claude-opus-4-6-v1` | Mapping for this enum member when selected in code. |
| `LLM_MODELS_CLAUDE_SONNET_4_6` | `anthropic.claude-sonnet-4-6` | Mapping for this enum member when selected in code. |

The complete mapping and default model selection are in [llm.py](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/utils/llm.py#L89-L108). Setting an override for another enum member does not select it. The released preparation agent constructs the [default model configuration](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/preparation/agent.py#L54-L56).

A mapping changes only the deployment ID. Every model call still sends `reasoning_effort`: `none` by default and `medium` in the review steps. The mapped deployment must accept that parameter. See the [request parameters](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/utils/llm.py#L103-L125) and [review-step models](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/research/nodes.py#L319-L322).

Example environment fragment:

```dotenv
DIAL_URL=http://core:8080
LLM_MODELS_GPT_5_6_TERRA=<CORE_MODEL_DEPLOYMENT_ID>
```

## Logging

| Variable | Default | Description |
|---|---|---|
| `LOG_LEVEL` | `INFO` | Root and managed third-party logger level. |
| `DEEP_RESEARCH_LOG_LEVEL` | `INFO` | Independent level for `dial_deep_research` loggers. |
| `LOG_FORMAT` | Format below | Python logging format, including SDK/OpenTelemetry context. |
| `LOG_DATE_FORMAT` | `%Y-%m-%d %H:%M:%S` | Timestamp format. |
| `LOG_PAYLOADS` | `false` | Enables payload debug logging. Disabled excludes payload content at every level. |
| `LOG_PAYLOADS_MAX_LENGTH` | `2000` | Maximum characters per logged payload string; integer, at least `1`. |

Both level settings accept `DEBUG`, `INFO`, `WARNING`, `ERROR`, and `CRITICAL`, normalized to uppercase. The default `LOG_FORMAT` is:

```text
%(levelprefix)s | %(asctime)s | %(process)d | %(name)s | %(otel_context)s%(message)s
```

Defaults and the payload policy are defined in [settings.py](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/settings.py#L17-L50).

**Warning**
> Payload logging can expose research questions, retrieved content, and client prompts. The source limits this mode to local development; keep `LOG_PAYLOADS=false` in shared environments.

## Optional channels and tracing

| Variable | Default | Description |
|---|---|---|
| `ENABLE_PLAYGROUND_CHANNEL` | `false` | Registers `deep-research-playground`, a tool-calling agent without the preparation/research workflow. Uses the instance's application properties. |
| `ENABLE_ANNOTATIONS_DEMO` | `false` | Registers `deep-research-annotations-demo`, which returns a fixed report citing two PDFs attached by the caller, each at least three pages. It reads no application properties, runs no research, and calls no model. |
| `OPIK_TRACING_ENABLED` | `false` | Enables local Opik tracing. Requires the optional `tracing` dependency extra. |
| `OPIK_PROJECT_NAME` | `deep-research` | Opik project name; non-empty string. |

The flags are defined in [settings.py](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/settings.py#L69-L80); optional deployments are registered in [factory.py](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/factory.py#L50-L75). The demo's inputs are described in [its completion](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/annotations_demo/completion.py#L1-L15) and the [README](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/README.md#inline-citations-demo); with other attachments, it replies with what to attach.

The standard image installs main dependencies without the optional tracing extra. Enabling Opik without it raises an error during startup. See the [Docker dependency installation](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/Dockerfile#L16-L21), [optional dependency](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/pyproject.toml#L41-L45), and [startup tracing check](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/utils/tracing.py#L11-L30).

SDK telemetry is configured with `DIAL_APP_NAME` as its service name, tracing, and metrics. Its exporter settings are SDK/OpenTelemetry settings rather than additional fields in the backend's settings model. See [SDK initialization](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app/factory.py#L37-L48).

## Direct MCP connection secrets

Direct-mode connections use deployment-defined variable names, referenced by `mcp_servers[].connection`. Each variable holds one JSON object containing `url` and a non-empty `api_key`. There is no fixed `MCP_URL` or `MCP_API_KEY` runtime setting.

```dotenv
RESEARCH_MCP_CONNECTION={"url":"https://<MCP_HOST>/mcp","api_key":"<MCP_API_KEY>"}
```

The application property is `"connection": "$env:{RESEARCH_MCP_CONNECTION}"`. A missing variable, inline connection value, or `$env:{VAR|default}` form fails validation. See the [placeholder validator](https://github.com/epam/ai-dial-deep-research-backend/blob/0.4.0/src/dial_deep_research/app_properties.py#L54-L80) and [MCP connection modes](2.application-properties.md#connection-modes).
