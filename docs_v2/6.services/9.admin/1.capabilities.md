# DIAL Admin capabilities

DIAL Admin brings platform configuration and optional operational tools into one interface. This page maps its capabilities to the services they require; the linked Administering DIAL pages explain how to use each screen. For deployment and architecture, see [DIAL Admin](0.index.md).

## Core administration

With `DIAL_CORE_API_URL` configured, Admin calls DIAL Core directly using the user's token.

| Capability | Purpose | User guide |
|---|---|---|
| AI Gateway | Register models, applications, toolsets, routes, translators, application runners, and catalog schemas; configure endpoints, interfaces, pricing, and access. Inspect file-defined entries and manage entries in Core storage. | [AI Gateway](../../5.administering-dial-new/1.ai-gateway/0.index.md) |
| Artifacts | Manage shared skills, files, conversations, and prompts. | [Artifacts](../../5.administering-dial-new/2.artifacts/0.index.md) |
| Governance | Manage roles, API keys, folder permissions, interceptors, and publication review. Core enforces permissions and usage limits. | [Governance](../../5.administering-dial-new/6.governance/1.roles.md) |
| Global settings | Configure system-wide interceptors and other global properties. | [System properties](../../5.administering-dial-new/1.config-backup-and-global-settings.md#system-properties) |

Core's Configuration API is Preview. Available screens and entity fields depend on the frontend and Core versions; see the [Configuration API reference](../1.core/1.configuration/1.configuration-api.md).

## Optional operational services

| Capability | Purpose | Required service and configuration | User guide |
|---|---|---|---|
| Deployments | Build images; deploy, scale, and inspect models, applications, adapters, interceptors, and MCP servers; manage resources and firewall rules. | [DIAL Deployment Manager](../11.deployment-manager/0.index.md); [deployment settings](2.configuration/1.frontend.md#deployment-manager-and-mcp-containers). MCP containers use the same Deployments API. | [Deployments](../../5.administering-dial-new/3.deployments/0.index.md) |
| Evaluation [Preview] | Manage datasets and test suites, run model/application/MCP tests, and compare scores, cost, and timing. | [DIAL Evaluations](../10.evaluations/0.index.md); [evaluation settings](2.configuration/1.frontend.md#evaluation). | [Evaluation](../../5.administering-dial-new/4.evaluation/0.index.md) |
| Analytics [Preview] | Analyze usage in dashboards, query data, inspect sessions, and manage tables and enrichment/aggregation pipelines. | Analytics data-access service; optional enrichment runner and query assistant; [analytics settings](2.configuration/1.frontend.md#analytics). | [Analytics](../../5.administering-dial-new/5.analytics/0.index.md) |
| Admin Backend screens and transfers | Use the Entities, Builders, and Access Management screens; the Audit group, with the telemetry Dashboards, Activity Audit, and Usage Log; and whole-configuration import/export. | Optional Admin Backend; [backend settings](2.configuration/1.frontend.md#optional-admin-backend). The telemetry Dashboards read metrics through Admin Backend. Deployments and Analytics have their own transfer scopes. | [Import/export workflows](../../5.administering-dial-new/1.config-backup-and-global-settings.md) |

Optional service APIs must accept the user's identity-provider tokens and authorize the requested operations. Hiding a menu with `DISABLE_MENU_ITEMS` changes navigation; API authorization remains the responsibility of Core and each backend. Without Admin Backend, or with sign-in off, the interface treats every user as a full administrator.

## Branding and observability

Admin supports custom themes and icons, home-page links to DIAL Chat and documentation, and a Grafana link. Its Next.js server exports OpenTelemetry traces and logs and exposes Prometheus metrics or pushes metrics over OTLP. These runtime signals are separate from the Analytics screens. See [UI settings](2.configuration/1.frontend.md#appearance-and-navigation) and [OpenTelemetry](2.configuration/1.frontend.md#opentelemetry).
