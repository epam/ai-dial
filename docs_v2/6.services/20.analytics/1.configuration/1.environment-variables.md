# DIAL Analytics environment variables

This reference covers environment variables for platform engineers operating DIAL Analytics. It assumes the [service connections](0.index.md) are configured.

## Defaults

Defaults come from the [application.yml](https://github.com/epam/ai-dial-analytics/blob/0.23.0-rc.0/src/main/resources/application.yml) and [configuration documentation](https://github.com/epam/ai-dial-analytics/blob/0.23.0-rc.0/docs/configuration.md). `—` means no configured value. Actual defaults containing `localhost` are reproduced unchanged; container deployments need reachable service names.

## Ingestion and retention behavior

The poller and daily reconciliation share the same blob layout and target mappings.
Schedules use UTC. Disabling `POLL_ENABLED` leaves daily reconciliation and operator backfills available.
The poller's watermark is in memory; restart lookback controls its recovery window.
`POLL_FINALIZATION_LAG` must cover the longest request or stream; daily reconciliation recovers older arrivals.

Azure shared-key authentication needs both account name and key.
Otherwise Azure uses `DefaultAzureCredential`, a blob endpoint, and a managed identity with Storage Blob Data Reader access.
The storage account must have hierarchical namespace disabled. SAS tokens are unsupported.
For S3, the endpoint must select the correct region; credentials can come from workload identity or an access-key pair.

`sync.targets` is a list of table/mapping pairs. An external YAML file replaces the list when adding or removing targets.
At least one target is required. Each accepted record can produce a row in several targets.
`blob.overrides` supplies additional jclouds properties when needed.

**Warning**
> The shipped payload target stores raw content. Removing that target stops future capture; it does not delete stored content.
> Unset retention variables preserve live TTLs: new tables start with 90 days for payloads and one year for usage logs.
> Positive retention changes can expire existing rows. `-1` removes the TTL; `0` is invalid.

Payload retention cannot exceed usage-log retention. Retention changes require ClickHouse migrations to be enabled.
`SYNC_REQUEST_BODY_MODE=delta` stores only new chat messages; `whole-with-path` supports rollback from that format.
The signed cursor keyring can be replaced with `enrichment.cursor.keys` in external YAML.
Rotation adds a new key, selects it through `active-key-id`, and retains old verification keys while cursors remain in use.
An empty cursor secret leaves cursor integrity unenforced.

## Resource budgets

Query and preview spill thresholds must remain below their memory ceilings; `0` disables spilling.
Budget violations reject the request rather than sample or truncate query results.
Pipeline statement timeouts must remain below the runner's `ADAS_READ_TIMEOUT_MS`.
A group fetch can issue several statements, so its HTTP timeout also needs headroom for every heavy-column read.
Aggregate scheduling runs in ADAS; SQL and LLM enrichment scheduling runs in the separate runner.
