# DIAL OpenAPI to MCP 0.2.0

DIAL OpenAPI to MCP 0.2.0 is the first stable release of the bridge, and its patch release, 0.2.1, adds health endpoints and OpenTelemetry. This page summarizes both, with a link to the full notes of each. It is for platform engineers who plan a deployment or an upgrade.

| Version | Date | Type |
|---|---|---|
| [0.2.0](#020) | 2026-08-11 | First release |
| [0.2.1](#021) | 2026-08-20 | Patch |

The DIAL 1.47 and 1.48 platform releases pin 0.2.1. The upstream `CHANGELOG.md` has no entries for either release; it describes only an untagged 0.1.0.

## 0.2.0

Released 2026-08-11. [Release notes](https://github.com/epam/ai-dial-openapi-to-mcp/releases/tag/0.2.0)

**Added**

- A failed credential lookup reports its cause in the tool result's `_meta`. The status is `404` when the application has no such external service, and `401`, with a sign-in challenge, when the user hasn't signed in. Other failures are `500`. See [Credentials from external services](../1.configuration/0.index.md#credentials-from-external-services).

**Other**

- The documentation no longer claims a destination allowlist or egress control. The bridge calls any destination a request names; limit its egress with network policy.
- The repository is prepared for open source, and stale ORT rule-violation resolutions are removed.
- CI reuses its virtual environment.
- `cryptography` is upgraded from 49.0.0 to 50.0.0.

## Patch releases

### 0.2.1

Released 2026-08-20. [Release notes](https://github.com/epam/ai-dial-openapi-to-mcp/releases/tag/0.2.1)

- **Added:** `GET /health` and `GET /ready` for liveness and readiness probes. The image's Docker health check now calls `/health`, and the image also exposes port `9464`.
- **Added:** OpenTelemetry traces, metrics, and logs, off until an `OTEL_*_EXPORTER` variable is set. See [Observability](../1.configuration/1.environment-variables.md#observability).
- **Added:** A `null` or empty (`{}`) document is treated as no document, so the bridge offers its utility tools, `openapi_verify` and `openapi_convert`.
