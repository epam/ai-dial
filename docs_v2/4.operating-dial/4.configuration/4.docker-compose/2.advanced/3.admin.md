# Admin Panel

The current [advanced setup sample](https://github.com/epam/ai-dial-samples/tree/main/2-dial-advanced-setup) runs Admin Frontend directly against DIAL Core, without Admin Backend. For the service's purpose and dependencies, see [DIAL Admin](../../../../6.services/9.admin/0.index.md).

## Admin Frontend

Use the [Docker Compose example](../../../../6.services/9.admin/2.configuration/1.frontend.md#docker-compose-example) in the service reference. It sets `DIAL_CORE_API_URL`, leaves `DIAL_ADMIN_API_URL` unset, and configures Keycloak authentication. The frontend server forwards the signed-in user's token to Core.

Core's admin rules decide whether the user's token is accepted; the frontend's role settings don't restrict access. See [Authentication and administrator access](../../../../6.services/9.admin/2.configuration/1.frontend.md#authentication-and-administrator-access). The browser and the frontend container must be able to reach the same Keycloak issuer URL; Core must validate that issuer.

Optional Evaluation, Deployments (including MCP containers), and Analytics screens connect to separately deployed APIs. Their switches and URLs are listed in [Optional services](../../../../6.services/9.admin/2.configuration/1.frontend.md#optional-services). The advanced sample supplies Evaluation and the Analytics Realtime pipeline; Admin's newer Analytics screens need a separate data-access service. For the evaluation services' Compose settings, see the [evaluation Docker Compose example](../../../../6.services/10.evaluations/1.configuration/0.index.md#docker-compose-example).

## Admin Backend

The older [`dial-docker-compose-advanced/dial-2.x/docker-compose-base.yml`](https://github.com/epam/ai-dial/blob/main/dial-docker-compose-advanced/dial-2.x/docker-compose-base.yml) also deploys Admin Backend. Use [Admin Backend configuration](../../../../6.services/9.admin/2.configuration/2.backend.md) for its Compose fragment, database, OIDC settings, and shared configuration export volume.

In that setup, Admin Frontend sets `DIAL_ADMIN_API_URL` to the backend's internal URL and retains `DIAL_CORE_API_URL` for direct Core operations. Its `network_mode: "service:keycloak"` means Keycloak publishes the frontend port on its behalf; the newer sample instead publishes the frontend's port directly. Use the networking of the sample you deploy.
