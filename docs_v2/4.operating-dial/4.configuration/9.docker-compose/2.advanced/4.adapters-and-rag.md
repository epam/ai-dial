# Adapters & RAG

## OpenAI Adapter

From [`docker-compose-base.yml`](https://github.com/epam/ai-dial/blob/main/dial-docker-compose-advanced/dial-2.x/docker-compose-base.yml):

```yaml
adapter-openai:
  image: epam/ai-dial-adapter-openai:0.43.2
  platform: linux/amd64
  environment:
    DIAL_URL: "http://core:8080"
    WEB_CONCURRENCY: "3"
    DALLE3_DEPLOYMENTS: "dall-e-3"
```

### Environment variables

| Variable | Description |
|----------|-------------|
| `DIAL_URL` | DIAL Core internal URL. Used for file storage API calls. |
| `WEB_CONCURRENCY` | Number of Uvicorn worker processes. |
| `DALLE3_DEPLOYMENTS` | Comma-separated Azure OpenAI deployment names for DALL-E 3. |

:::note
The 2.x stack no longer sets `GPT4O_DEPLOYMENTS`, `GPT4O_MINI_DEPLOYMENTS`, or `DIAL_USE_FILE_STORAGE`. Per-model deployment names are declared in [`config.json`](../../core/config-json/models) instead; `DALLE3_DEPLOYMENTS` remains because image models still need the adapter to know which deployments return images. See [Adapter configuration](../../adapter-configuration) for variables the adapter still accepts but this stack does not set.
:::

See [Adapter configuration](../../adapter-configuration) for the full adapter environment variable reference.

## DIAL RAG

[`docker-compose-full.yml`](https://github.com/epam/ai-dial/blob/main/dial-docker-compose-advanced/dial-2.x/docker-compose-full.yml) extends the base setup by including `docker-compose-base.yml` and adding the RAG service:

```yaml
include:
  - path: ./docker-compose-base.yml

services:
  dial-rag:
    image: ghcr.io/epam/ai-dial-rag:0.43.0
    platform: linux/amd64
    env_file: .env
    environment:
      DIAL_URL: "http://core:8080"
      DIAL_RAG__INDEX_STORAGE__USE_DIAL_FILE_STORAGE: "true"
      DIAL_RAG__REQUEST__INDEXING__DESCRIPTION_INDEX__LLM__DEPLOYMENT_NAME: "gpt-5"
      DIAL_RAG__REQUEST__QA_CHAIN__CHAT_CHAIN__LLM__DEPLOYMENT_NAME: "gpt-5"
      DIAL_RAG__REQUEST__QA_CHAIN__QUERY_CHAIN__LLM__DEPLOYMENT_NAME: "gpt-5"
    restart: always
```

### Environment variables

| Variable | Description |
|----------|-------------|
| `DIAL_URL` | DIAL Core internal URL. |
| `DIAL_RAG__INDEX_STORAGE__USE_DIAL_FILE_STORAGE` | Store document indexes in DIAL Core's file storage. |
| `DIAL_RAG__REQUEST__INDEXING__DESCRIPTION_INDEX__LLM__DEPLOYMENT_NAME` | Model deployment used for generating document descriptions during indexing. |
| `DIAL_RAG__REQUEST__QA_CHAIN__CHAT_CHAIN__LLM__DEPLOYMENT_NAME` | Model deployment used for answering questions over indexed documents. |
| `DIAL_RAG__REQUEST__QA_CHAIN__QUERY_CHAIN__LLM__DEPLOYMENT_NAME` | Model deployment used for rewriting the user question into a retrieval query. |

:::note
RAG requires a working model deployment (`gpt-5` in this stack) configured in `config.json` with a valid API key. Without it, indexing and QA requests fail.
:::
