# Release Notes

The purpose of this document is to provide a quick summary of all the biggest new features added in this version and provide some additional description, video, or tutorials for major features.

## Brief Summary

With this release **DIAL Chat 2.0** becomes the only chat shipped with the DIAL platform, and it now lets users **invoke Agent Skills directly from a conversation**. On the DIAL Core side, the headline is **API Translators** together with a reworked, fully configurable **deployment interfaces** model, so a deployment can serve an API it does not speak natively. Rate limits move to **fixed calendar windows** with visible reset times, and the **Evaluation Framework** now covers the Responses and Anthropic Messages APIs, run cancellation, and run costs.

## Major Enhancements

**DIAL Chat 2.0 Is Now the Default**: As announced with 1.47, DIAL 1.48 is the first platform release that ships only the new chat line. This release adds a lot of polish on top of the 2.0 rebuild: a new **Settings → Preferences** tab, a rebuilt text and voice input, prompts from the library inserted at the caret (and undoable with Ctrl+Z), grouped application visualizers ported from the legacy chat, and a **Usage** view that shows DIAL Core limit reset times using calendar period names. Citations became much more precise — DOCX citations navigate to the exact passage, DOCX/PPTX table rows are highlighted from annotation anchors, and PDF citations support region selectors.

<!-- <img src="../../img/dial-chat-1.48.png" width="357"/> -->

* *Agent Skills in Conversations (Preview)**: After 1.46 introduced skills as a DIAL Core resource and 1.47 added end-to-end governance in DIAL Admin, 1.48 closes the loop for end users. Users can now attach a skill to a message in DIAL Chat and **invoke their own skill** from Quick Apps agents, with skills handled as full DIAL resources in the Quick Apps backend. DIAL Core adds a `skillsSupported` feature flag, lets applications pass custom skills in the unified chat completion request, and automatically shares skills declared in the config with the applications that reference them. The result is that a skill authored, reviewed, and published once can be used consistently by both people and agents across the organization. The feature is in Preview: skill usage in DIAL Chat is turned off by default and is enabled with `SKILL_USAGE_ENABLED`, and skills in Quick Apps require DIAL Core `0.48.0` or later.

<!-- <img src="../../img/skills-in-chat.png" width="357"/> -->

**API Translators and Unified Deployment Interfaces**: DIAL already exposes the Chat Completions, OpenAI Responses, and Anthropic Messages APIs through one gateway. With **translators**, a deployment can now serve an API it does not natively speak: DIAL Core hands the request to a translator service, which converts it (for example, Anthropic Messages → OpenAI Chat Completions) and calls DIAL Core back on an API the model does support. Usage, cost, and request limits are counted once — on the callback — so a translated request never consumes quota twice. Translators are declared once at the config root and referenced by name from a deployment's `interfaces`. The interfaces model itself became much richer: per-interface `baseUrl` and `mode` (`passthrough` or `translator`), `features`, `defaults`, `defaultHeaders`, and `overridePaths`, also available on upstreams. DIAL Admin gets a new **Platform Translators** section and per-interface endpoint overrides (part of the full DIAL Core API migration in the Admin Catalog, currently in Preview), making it possible to, for example, run Claude Code against models that only offer an OpenAI-compatible API — without writing a custom adapter.

<!-- <img src="../../img/translators.png" width="357"/> -->

**Fixed Calendar Windows for Rate Limits**: Daily, weekly, and monthly token limits (and `requestDay`) are now enforced over **fixed calendar windows** instead of rolling ones, anchored by a single deployment-wide setting. This matches how organizations actually budget and charge back AI usage — "this month" means the calendar month — and makes limits predictable for end users, who can now see exactly when their quota resets directly in DIAL Chat.

**Evaluation Framework Enhancements**: The evaluation backend now supports agents and models exposed through the **OpenAI Responses API** and **Anthropic Messages API**, so test suites can cover the same APIs used in production. Running test suites can be **cancelled** from DIAL Admin and stop immediately, each test case gets an **overall score**, run and deployment **costs** are available through new endpoints, and try-out now works for multi-request test suites. Runs also execute in parallel up to the configured run limits, instead of being capped by a fixed thread pool. Together with the multi-turn support added in 1.47, this makes evaluation a practical part of the agent lifecycle, not just a one-off check.

## Additional Notes

For full technical release notes with all bug fixes and additional features, please consult the [upgrade guide](upgrade-to-1.48.md) with all the tags for each component, as well as the DIAL documentation.

**DIAL Core**
* **Deployment Lookup:** New `GET /v1/deployments/{deployment_id}` endpoint; deployment listings expose per-interface configs; Anthropic-compatible models listing is supported.
* **Config File Migration:** New endpoint to migrate config files into dynamic settings, with clearer migration results.
* **Security:** Client secrets are masked in API responses; the user-info API now returns `userDisplayName`.
* **Responses API:** Upstream-aware routing for encrypted content, and background jobs now respect the interfaces config.

**DIAL Admin**
* **Analytics:** Composite SQL queries across multiple sources, a pipeline registry with enrich and aggregate kinds, JSON editing of table schemas, and a Create Evaluator modal.
* **Activity Audit:** Extended to analytics tables, pipelines, and platform models, with a new "Since Creation" range.
* **Config Files:** Config file entities can be viewed in the UI with a read-only toggle.
* **Roles for Platform Assets:** Platform applications and toolsets now support roles.
* **Deployment Manager:** Supports multiple scoped Git credentials per domain (medium-priority changes — see the upgrade guide).
* **Catalog Preview:** The full DIAL Core API migration in the Catalog is available as a Preview; a new optional `ANALYTICS_CONVERSATIONS_ENABLED` flag controls the Conversations view in Analytics.

**Model Adapters**
* **OpenAI Adapter:** Exposes Azure OpenAI v1 API endpoints, returns reasoning tokens in the `reasoning_content` field of Chat Completions, adds Alibaba context caching, and supports per-upstream AWS credentials and STS role assumption for Bedrock-hosted models.
* **Bedrock Adapter:** AWS STS session tags are now applied to all Bedrock clients and include the model id (breaking change — see the upgrade guide); request timeout is configurable via `REQUEST_TIMEOUT_SECONDS`.
* **Vertex AI Adapter:** Supports EKS Pod Identity via `AWS_CONTAINER_AUTHORIZATION_TOKEN_FILE`.

**DIAL Chat**
* **Start Screen Customization:** A configurable description below the greeting (`WELCOME_SCREEN_DESCRIPTION`), an option to show all conversation starters, and an option to hide the version in the footer.
* **Custom Client Variables:** Operators can pass public client-side settings through `CUSTOM_CLIENT_VARIABLES`.
* **Migration from Chat 0.4x:** `AUTH_LEGACY_COOKIE_NAMES` clears leftover authentication cookies from the previous chat on the same origin.

**Quick Apps**
* **Dynamic Tools Context:** Agents can work with a dynamic tools context; static tools and `reasoning_effort` are forwarded to deployment tools, and tool annotations (citations) are propagated to the final answer.
* **Tool Deferral:** Large toolsets can be loaded on demand instead of eagerly.

**Observability**
* **Analytics Realtime:** Supports the OpenAI Responses and Anthropic Messages APIs, with new Grafana dashboards for both.
* **Structured Logging:** Added to evaluation metrics; Mind Map adds OpenTelemetry and a health check endpoint.
