# Release Notes

The purpose of this document is to provide a quick summary of all the biggest new features added in this version and provide some additional description, video, or tutorials for major features.

## Brief Summary

With this release **DIAL Chat** lets users **invoke Agent Skills directly from a conversation** (Preview). On the DIAL Core side, the headline is **API Translators** together with more flexible **model connection settings**, so a model can be used through an API it does not support natively. Usage limits move to **calendar periods** with visible reset times, and the **Evaluation Framework** now covers more API types, run cancellation, and run costs.

## Major Enhancements

**DIAL Chat 2.0 Is Now the Default**: As announced with 1.47, DIAL 1.48 is the first platform release that ships only the new chat line. This release adds a lot of polish on top of the 2.0 rebuild: a new **Settings → Preferences** tab, a rebuilt text and voice input, prompts from the library inserted at the caret (and undoable with Ctrl+Z), grouped application visualizers ported from the legacy chat, and a **Usage** view that shows DIAL Core limit reset times using calendar period names. Citations became much more precise — DOCX citations navigate to the exact passage, DOCX/PPTX table rows are highlighted from annotation anchors, and PDF citations support region selectors.

<!-- <img src="../../img/dial-chat-1.48.png" width="357"/> -->

**Agent Skills in Conversations (Preview)**: After 1.46 introduced skills in DIAL Core and 1.47 added end-to-end governance in DIAL Admin, 1.48 brings skills to end users. Users can now pick a skill from the catalog or the message input and **use it directly in a DIAL Chat conversation**, so a skill that was authored, reviewed, and published once can be reused by anyone in the organization who has access to it. DIAL Core and Quick Apps now also support skills behind the scenes, laying the groundwork for agents to use them; configuring skills in the Quick Apps editor will follow in the next release. The feature is in Preview and is turned off by default.

<!-- <img src="../../img/skills-in-chat.png" width="357"/> -->

**API Translators and Flexible Model Connections**: DIAL already offers several industry-standard APIs — OpenAI Chat Completions, OpenAI Responses, and Anthropic Messages — through one gateway. With **translators**, a model can now be used through an API it does not support natively: DIAL converts the request on the fly and returns the answer in the format the client expects. Usage, cost, and limits are still counted only once, so translation never doubles anyone's consumption. Administrators also get much finer control over how each model is connected and which capabilities it offers through each API, and DIAL Admin adds a dedicated **Translators** section to manage this without editing configuration files (in Preview). In practice this means, for example, that developer tools like Claude Code can run on models that only offer an OpenAI-compatible API — with no custom integration work.

<!-- <img src="../../img/translators.png" width="357"/> -->

**Calendar-Based Usage Limits**: Daily, weekly, and monthly limits now follow **calendar periods** instead of rolling windows. This matches how organizations actually budget and charge back AI usage — "this month" means the calendar month — and makes limits predictable for end users, who can now see exactly when their quota resets directly in DIAL Chat.

**Evaluation Framework Enhancements**: Evaluations now support agents and models that use the **OpenAI Responses API** and **Anthropic Messages API**, so test suites can cover the same APIs used in production. Running test suites can be **cancelled** from DIAL Admin and stop immediately, each test case gets an **overall score**, the **cost** of each run and deployment can now be tracked, and multi-step test suites can be tried out before running. Test runs also execute more in parallel, so results arrive faster. Together with the multi-turn support added in 1.47, this makes evaluation a practical part of the agent lifecycle, not just a one-off check.

## Additional Notes

For full technical release notes with all bug fixes and additional features, please consult the [upgrade guide](upgrade-to-1.48.md) with all the tags for each component, as well as the DIAL documentation.

**DIAL Core**
* **Configuration Migration:** Existing configuration files can now be migrated into settings managed through DIAL Admin.
* **Security:** Secrets are hidden in API responses, and users are shown by their display name instead of a technical ID.
* **Broader Model Support:** Anthropic-compatible model listings are now supported.

**DIAL Admin**
* **Analytics:** Queries that combine several data sources, reusable data-processing pipelines, and easier creation of evaluators.
* **Activity Audit:** Now covers analytics tables, pipelines, and platform models, with the option to view the full history since creation.
* **Configuration Visibility:** Configuration files can be viewed in the Admin UI in read-only mode.
* **Access Control for Platform Assets:** Platform applications and toolsets now support role-based access.
* **Deployment Manager:** Supports multiple Git credentials per domain.

**Model Adapters**
* **OpenAI Adapter:** Adds support for the latest Azure OpenAI API, shows model reasoning in responses, adds context caching for Alibaba models to reduce cost, and supports separate AWS credentials per connection for models hosted on AWS Bedrock.
* **Bedrock Adapter:** Improved cost attribution in AWS with model details added to every request, and support for longer-running requests.

**DIAL Chat**
* **Start Screen Customization:** Administrators can add a welcome description under the greeting, show all conversation starters, and hide the version label.
* **Smoother Migration:** Users moving from the previous chat version no longer run into sign-in issues caused by old browser data.

**Quick Apps**
* **Smarter Tool Use:** Agents get better context about the available tools, and citations from tools are carried through to the final answer.
* **Large Toolsets (Preview):** Large toolsets are loaded only when needed, keeping agents fast and focused.
* **Better Error Recovery:** When a tool fails, the agent now sees the actual error and can react to it more sensibly.

**Observability**
* **Realtime Analytics:** Usage through the OpenAI Responses and Anthropic Messages APIs is now tracked, with new ready-made dashboards for both.
