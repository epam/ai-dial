DIAL Deployment Manager Backend configuration

Deployment Manager Backend configures cluster access, image builds, workload lifecycles, storage, and authentication through Spring Boot properties and environment variables. This reference is for platform engineers who deploy the backend. For the settings on DIAL Admin and in the cluster, start with Configuration overview.

Version scope​

Defaults below are checked against Backend 0.22.0 application.yml, with behavior described in that release's configuration reference. The YAML is authoritative where its defaults differ from the reference tables: for example, Knative startup is 60 seconds and informer resync is 600 seconds.

The development reference is newer than this release and removes the NIM configuration. The 0.22.0 reference table lists KServe's informer interval as K8S_NIM_DEPLOYMENT_INFORMER_RESYNC_INTERVAL_SEC, but the released YAML reads K8S_KSERVE_DEPLOYMENT_INFORMER_RESYNC_INTERVAL_SEC; the tables below follow the YAML.

Spring configuration​

Environment variables, external YAML/properties, command-line arguments, and Java system properties can supply configuration. SPRING_CONFIG_ADDITIONAL_LOCATION=file:/config/override.yml adds an external file. Normal Spring precedence applies; external files do not override higher-priority environment variables or command-line options.

Full Kubernetes templates can be overridden through Spring configuration, including service accounts, pod security, volumes, annotations, and resource defaults. For example:

app:
  knative-service-config:
    spec:
      template:
        spec:
          serviceAccountName: managed-workload
          automountServiceAccountToken: false

API-key authentication​

API-key authentication is optional and requires OIDC security mode. The backend validates an Api-Key header through Core's GET /v1/user/info. It does not maintain its own store of API keys.

VariableDefaultDescription
API_KEY_ENABLEDfalseAccept Core API keys alongside OIDC tokens.
API_KEY_CORE_URL—Required Core base URL when enabled.
API_KEY_CACHE_TTL_SECONDS60Cache lifetime for successful introspection. Revocation can take up to this interval to be observed.
API_KEY_CACHE_MAX_SIZE10000Maximum cached introspection results.
API_KEY_REQUEST_TIMEOUT_MS3000Core introspection timeout, in milliseconds.
API_KEY_ROLES_MAPPING—Maps project-key roles to backend roles.
API_KEY_STARTUP_PROBEtrueProbe Core at startup; unreachable Core aborts startup.

Project-key callers use API_KEY_ROLES_MAPPING. JWT-rooted per-request keys use the default OIDC role, principal, and email mappings instead. At least one of those role mappings must be nonempty. When both Authorization and Api-Key are present, the token path takes precedence.

Core non-success responses and malformed user-info responses become 401; transport failures become 503. Failures are not cached. See the upstream API-key reference for the two response shapes and mapping examples.

Warning

H2 is intended for development and testing. Its file-copy backup/restore is unreliable; use PostgreSQL or SQL Server for production and keep database backups together with the cluster and registry recovery plan. Replace the example/default database credentials.

SQL Server's upstream configuration recommends a case-sensitive, accent-sensitive collation such as SQL_Latin1_General_CP1_CS_AS. Standard Spring datasource properties can override the generated JDBC URL. Migration locations are selected from datasource.vendor; the DB_VENDOR name in the upstream documentation table is not used by the 0.22.0 YAML.

Private Git repositories​

Entries use host and optional path to scope credentials. HTTPS/HTTP credentials use user and token; SSH credentials use sshKeyPath and sshKnownHostsPath, with files mounted into the backend. Store credential values in secrets, for example Helm manager.secrets.

[
  {"host":"git.example.com","path":"team/service-a","user":"builder","token":"<REPOSITORY_TOKEN>"},
  {"host":"git.example.com","path":"team","user":"builder","token":"<GROUP_TOKEN>"}
]

An exact host wins over parent domains, then the longest matching host wins. Within that host, an exact repository path wins over a group prefix, which wins over a host-wide credential. Host matching is case-insensitive; paths are case-sensitive. Duplicate (host, path, authentication type) scopes fail startup in 0.21.0 and later. See Backend 0.21.0.

Node pools​

VariableDefaultDescription
NODE_POOLSEmptyYAML list of scheduling presets.
NODE_POOL_DEFAULTEmptyDefault pool ID for new deployments.
NODE_POOL_DEFAULT_MODELEmptyModel-serving default pool ID; takes precedence over the catch-all default.

Each entry needs a unique immutable id and display name. Optional description, nodeSelector, affinity, and tolerations describe scheduling. Selectors and affinity replace template values; tolerations append to existing values. These are scheduling presets for existing Kubernetes nodes, not a node-provisioning service.

- id: cpu-pool
  name: CPU pool
  nodeSelector:
    workload: cpu
- id: gpu-pool
  name: GPU pool
  nodeSelector:
    workload: gpu
  tolerations:
    - key: dedicated
      operator: Equal
      value: gpu
      effect: NoSchedule

Defaults are persisted when a deployment is created. Changing a default does not migrate existing deployments. Changing a pool's scheduling fields affects deployments using it on their next redeploy; changing its display name is safe. Renaming its id breaks references. The old NODE_POOL_LABEL_KEY has no effect.

Network policy​

CILIUM_NETWORK_POLICIES_ENABLED defaults to false. When enabled, the backend creates Cilium policies for build jobs and workloads using configured global and per-image/per-container domain rules. Cilium must be installed and the backend must have policy RBAC. UI domain lists alone do not enable enforcement. See the upstream Cilium deployment guide.
